## 这份初测之后怎样继续

1. 保持当前 Wi-Fi、VPN 状态与配置，先在新版本完成一次快速检查。默认仅查询系统 DNS，不需要自建 HTTPS 服务。
2. 若愿意增加明文 DNS 对照，明确勾选原始 UDP/TCP，在确认框核对解析器、端口、同一查询域名和记录类型，再开始。公共预设只影响原始探针，不会更改系统 DNS。
3. 若系统错误仍出现，先检查域名和 VPN 当前生效的 DNS 设置。保存当前结果为内存基线并导出；每次只调整一项设置，然后按基线相同计划复测。不要仅因这份报告就关闭证书校验、切换全部 DNS 或覆盖唯一可用配置。
4. 0.3.0 不支持把这份导出的历史 JSON 重新导入为运行基线；需要在同一应用进程内重新采集并保存基线。切换计划或网络时，要重新解释可比性。
5. 若目标是判断请求是否绕过 VPN，需要配合受控解析器、代理核心或网关日志关联请求。应用内地址结果只能说明本次观察，不能完成全机泄露验收。

## 专业项目应该怎样填写

底部“测试”页提供“系统 DNS 检查”“DNS 连通对照”“HTTPS 出口核验”三个场景。先阅读用途和将要重设的内容，再点击“应用填写建议”；此操作只填表，真正发送请求仍需点击开始并确认目标。也可以直接选择项目开关；启用后才展开对应字段。关闭的项目保留进程内草稿，但不参与校验和本次请求。

| 字段/选择 | 填写建议 | 常见误填与解释 |
|---|---|---|
| 系统 DNS 域名 | 初次用 `example.com`；受控实验才替换为自己的 ASCII 域名 | 不填 `https://`、端口、路径或 IP；中文域名需使用自己确认正确的 ASCII 表示 |
| 原始 DNS 解析器 | 填数字 IPv4/IPv6；可以显式选择当前网络 DNS 或已有公共预设 | 不填 DoH URL、Private DNS 主机名、订阅链接；IPv6 不带方括号或作用域后缀 |
| 原始 DNS 端口 | 默认 `53`；自建服务才改为已知监听端口 | 范围 1–65535；填 `853` 并不会把 UDP/TCP 探针变成 DoT |
| 原始 DNS 查询域名 | 比较解析方式时显式“沿用系统查询域名”；独立实验可另填 | 复制按钮只填值，不自动启用探针；独立域名不能被静默覆盖 |
| UDP / TCP | 需要协议对照时分别选择；仍允许只选一个 | 两者独立执行，无自动重试或 TCP 回退；两者均未选时不要求原始目标 |
| A / AAAA | A 查询 IPv4 地址记录；AAAA 查询 IPv6 地址记录 | 记录类型不决定传输路径；IPv4 解析器可以返回 AAAA，IPv6 解析器也可以返回 A |
| HTTPS 服务源地址 | 只在自己已部署或获准使用兼容回显服务时填写，例如 `https://echo.your-domain.example:8443` | 该地址仅示意格式，必须替换；普通网站、测速站、Clash 控制面和 DoH 地址不等于兼容服务 |
| 回显路径与证书 | 工具固定请求 `/v1/echo` 并验证本次随机请求标记；使用系统信任的有效 TLS 证书；返回 HTTP 200、`Content-Type: application/json`、未压缩且不超过 4096 字节的兼容 JSON | 输入只含源地址，不含路径、账号、查询参数或片段；不要关闭证书验证来绕过错误；电脑上的回环测试 fixture 不是手机可直接访问的公共部署 |
| 预期服务端来源 IP | 可留空；已有可靠预期时填写回显服务应看到的数字地址，用英文逗号分隔 | 不是 DNS 解析器 IP、VPN 虚拟 DNS IP 或回显网站的目标 IP；留空只记录观察 |
| 信任回显服务 | 理解该服务如何生成来源 IP 声明后再勾选 | 这是对来源声明的信任，不是允许不安全 TLS，也不能由填写模板自动勾选 |
| IPv6 专项范围 | 保持在范围内时仍可出现“观察不足” | 取消该项只记录不适用，不会关闭手机 IPv6，更不会修复 IPv6 旁路 |

当前场景操作会重设探测开关；DNS 场景填入 `example.com`、A 和端口 53，DNS 对照从当前网络快照选数字目标，缺失时留空。HTTPS 场景保留已填写的端点与预期地址，但清除信任勾选，要求重新确认；不会发明公共回显服务或从本次结果反推预期 IP。应用场景前的对话框明确说明这些修改。另有“填入当前网络 DNS”和“与系统查询使用同一域名”按钮，点击只改对应字段，不发送请求。域名格式示例必须替换成自己配置并获准测试的真实域名。已有协议说明见 [RAW-DNS.md](../../guides/RAW-DNS.md)，配置副本与系统设置流程见 [DNS-REPAIR.md](../../guides/DNS-REPAIR.md)。

## 首页与结果区的最小改进

初审的 0.3.0 把目标说明、多个操作按钮、完整建议与完整证据放在一条长滚动页面。现有 [MainActivity.kt](../../../app/src/main/kotlin/dev/proxyaudit/android/MainActivity.kt) 已改为底部三个主要区域：**首页 / 测试 / 结果**；修复中心作为首页和结果页中的任务入口。首页默认显示快速检查，测试页按开关展开字段，结果页先显示四行摘要和下一步，详细证据默认折叠。切换页面会收起键盘并回到对应区域顶部，当前导航项有文字和选中态；所选页、详情展开与输入草稿仅在进程内保存。

下面是这一结构的验收目标与后续优化依据，不是官方强制规范；源码中的对应实现仍需按下方清单实际验证：

| 区域 | 最小改进 | 必须保留的行为 |
|---|---|---|
| 首屏导航 | 固定“首页 / 测试 / 结果”三项，首页含专业测试和修复中心入口；当前任务有文字标识 | 页面切换仅浏览；不更改 VPN、不自动检查、不申请新权限 |
| 首屏内容 | 产品名称、一句用途、简短当前状态、一个主要“开始检查”按钮；原始 DNS 开关及目标作为次级选项 | “仅本应用”“明文 DNS”与执行前目标确认不能藏到无法发现的位置 |
| 运行状态 | 就近显示正在进行的项目和取消按钮；取消后显示等待资源释放 | 不用虚构进度百分比；仍忙时不可开始另一项，不把取消当安全阻断 |
| 结果摘要 | 将系统 DNS、原始 UDP、原始 TCP、HTTPS 的实际状态放在最前面；未启用明确写“未执行” | 分开“是否取得结果”和“是否有路径证据”，不合成为安全分数 |
| 下一步 | 摘要后展示一项主要行动建议；完整逐项诊断位于可展开详情 | 不因结果多而隐藏取消、条件不稳、域名不一致或证据不足提示 |
| 详细证据 | 目标/时间/响应码/网络快照/限制按组折叠；摘要附近保留“查看详细证据” | 地址、错误和局限仍可完整查看、复制和导出；折叠状态不改变报告 |
| 对照操作 | 有可用报告时再显示保存基线；有基线时显示复测/对照，清楚标出基线状态 | 基线进程内保留、相同计划再次确认、冻结导出及旧回调隔离保持原逻辑 |
| 专业填写 | 三个项目各自启用后展开字段；每字段用标签、简短用途、例子和就地错误 | 隐藏字段的残留值不参与本次运行；全未选时仍拒绝开始 |
| 辅助操作 | 演示、导出、清除和完整限制放在次级区域 | 演示持续标识为虚构，不能作为真实基线；清除说明只影响内存 |

当前实现继续使用原生 `Activity`、`LinearLayout`、`ScrollView`、`Button`、`CheckBox`、`Spinner` 和 `EditText`，本次界面重构未新增运行依赖，也不要求 root、额外辅助服务或占用 VPN。固定导航只承载主要区域，“开始”“导出”“取消”仍是区域内动作；返回修复页上一层时应保持草稿和结果。这采用 Android 的内容/导航分区原则，并非宣称使用了完整 Material 3 组件库。[Android App Anatomy](https://developer.android.com/design/ui/mobile/guides/layout-and-content/app-anatomy)、[Android 导航与控件设计](https://developer.android.com/design/ui/mobile/guides/foundations/translate-designs)

输入控件要有持续标签，出错时在对应字段旁说明如何改，并聚焦首个错误字段；不要只靠颜色或一闪而过的提示。可以用原生 `EditText.error` 与辅助文本实现这一信息结构，无需安装 Material 运行依赖。字段说明与就地错误的依据是官方 Material 文本字段文档；该页属于 Material 2，仅用于这些基本模式参考。[Material 文本字段](https://m2.material.io/design/components/text-fields.html)

端口使用数字键盘，域名/IP/HTTPS 输入支持适当的文本键盘；“下一项/完成”用于移动焦点或关闭键盘，不能越过目标确认直接发请求。字段间标签关系、展开状态和当前任务应能被辅助技术识别。[Android 输入法类型与动作](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/style)

触控区域至少 48×48 dp；正文与背景保持足够对比，状态同时有明确文字。重点检查 360 dp 宽度、放大字体、键盘弹出和系统手势栏，不能把固定导航或主操作压在不可触及区域。[Android 无障碍建议](https://developer.android.com/guide/topics/ui/accessibility/apps)、[Android 系统栏](https://developer.android.com/design/ui/mobile/guides/foundations/system-bars)

## 现有测试怎样复用

[MainActivityTest.kt](../../../app/src/test/kotlin/dev/proxyaudit/android/MainActivityTest.kt) 当前使用 Robolectric，覆盖 API 29/35 框架模拟；文件注释已说明不是设备/VPN 探测。保留快速默认值、确认取消、raw-only、A/AAAA 与目标族、非法输入、进程内旋转、演示标记、基线冻结、对照导出及 SAF 旧回调等断言。布局重构时调整寻找控件的方法，不删除这些行为保护。

现有辅助函数主要用整段按钮文字和 hint 查找控件；导航与面板已有稳定 tag。新界面可继续给输入和摘要设置稳定 ID/tag，以避免改一句文案就导致无关用例失效；同时保留专门的用户文案断言。已新增的源码用例覆盖单区显示、场景填表与独立开始确认、不发明 HTTPS 端点/预期 IP/信任、四行摘要与折叠详情、字段错误和回显契约。尚需按清单核对未启用项不校验、详情与导航旋转、字体/键盘和辅助技术。场景覆盖原值必须经过说明；不能把“用户主动应用预设”与“切换页面静默覆盖”混为一谈。

初测摘要回归可以使用显式标注的合成 `RunReport` 来模拟相同状态，但不得把 `[REDACTED]` 伪装成真实 IP 交给验证逻辑，也不能把合成地址称为用户实际地址。若测试要保留“域名是否相同”这一未知性，应在导出报告解读层单独表达，不能仅因两个占位符相等就构造同域名事实。

**本指南的手工 UI、无障碍和新版设备验收仍待用户执行。** 已知演示详情会出现“系统解析已返回地址”这类未在单项内再次标注虚构来源的文字，导致两个框架模拟用例失败；页面仍有显著演示标签，演示报告仍不能保存为真实基线。这是需要修正的证据表达问题，不能因为外层标签存在就忽略失败，也不能据此声称应用已经产生真实泄露。该项列为下一轮恢复开发时的 P0，用户确认前不改代码。
