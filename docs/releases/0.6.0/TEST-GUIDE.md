继续跳过模拟器。以下是0.6.0验收方案；部分步骤已有后续真机记录，覆盖范围见[当前验证](../../testing/CURRENT-STATUS.md)，本清单本身不表示全部通过。

安装本版APK，进入“开始网站与网络诊断”。保留 https://chatgpt.com/ 或填出问题的HTTPS网站；代理状态选“代理已开启”。不必填预期出口IP、DNS IP或配置文件。

先选“仅检查本机环境”，查看正常回应、受控超时、拒绝连接及画像。再选“开始自动诊断”，查看定位和DNS/连接/TLS/HTTP/正文阶段。需要DNS对照时勾选扩展，App自动取当前网络DNS；此实验发送明文查询，不应误认为系统加密解析。

| 编号 | 操作 | 核验点 |
|---|---|---|
| D01 | 打开页面、选预设、修改网址 | 未开始时不发送请求；域名不被静默纠错 |
| D02 | 仅检查本机 | 三个预定场景正确识别，服务关闭，无网站请求 |
| D03 | 代理开启诊断网站 | 显示网络/代理选择、解析候选、TLS参数与HTTP状态，缺失有具体原因 |
| D04 | 浏览器能开但App失败 | 查分应用、代理选择和最早失败层；不读取浏览器账户或直接归因DNS |
| D05 | 3xx/403/429 | 保留连接/TLS/HTTP响应；不自动跳转，不称TLS失败 |
| D06 | 运行中取消，再启动其他检查 | 停止后续实验；旧资源释放前无重叠工作 |
| D07 | 慢请求期间切网/重连VPN | 记录条件改变并停止；稳定后新运行重新采集 |
| D08 | 扩展DNS | A/AAAA各有UDP/TCP；未完成四项不能称四项全成功 |
| D09 | 脱敏/完整导出 | 默认隐藏网络标识，保留阶段、状态和地址数；完整仅本地保存 |
| D10 | 文件选择器旋转/返回/再次导出 | 旧回调不消费新报告，进程丢失数据不会写成成功 |
| D11 | 既有DNS/出口/修复入口 | 严格回显、配置副本、基线、读回和复测保持可用 |

记录手机/API、客户端/核心版本、VPN/TUN或本地代理模式、诊断包 dev.proxyaudit.android 是否纳入、runId、实际结果与文件名。核心的规则/全局模式与Android是否接管此App分别记录。

## 按失败层处理

- DNS：查解析事件和代理是否代解析，可用当前DNS四项对照；无记录、错误响应和超时分开处理。
- 连接：有地址却连不上，查对端、代理隧道和路由；暂时性错误自动复核。
- TLS：查安全错误分类、设备时间、目标与证书；不关闭验证。
- HTTP403/429：已收到服务响应，继续查访问策略、限流、登录或验证页面；单个状态不能证明具体封禁原因。
- 正文：首部成功但读取超时，查读取/链路稳定性；达上限属于部分读取。
- 代理开启而不见VPN：查客户端模式、分应用、工作资料，再看请求的代理选择；不先换DNS。

## 专项验收

自有/获准端点验证：过期/错主机名/不受信任证书、拒连、慢滴流、NXDOMAIN、空答案、UDP失败而TCP成功。没有对应环境保留待测，不随机挑公共IP制造异常。

性能对照保持同域、目标、记录类型与预算；A和AAAA分开建计划，多次观察保留全部结果。少量样本不能证明总体分位数或修复因果。

DNS泄露专项用唯一查询标记、解析/权威日志与受控网关/代理日志关联。权威日志通常看到递归器来源，单独不足以证明手机路径；避免第二个抓包VPN替换待测VPN。
