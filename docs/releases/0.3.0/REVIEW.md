## 本版范围

本版把“输入完整实验参数”之外的路径补齐：确认后快速检查系统解析、基于观察给出有限建议、离线生成 Mihomo DNS 配置副本、保存基线并按相同计划复测。专业模式保留 HTTPS、系统 DNS 与原始 UDP/TCP 选择。

| 能力 | 当前实现 | 证据边界 |
|---|---|---|
| 快速 DNS 检查 | 固定 `example.com`，默认只执行系统 DNS；原始 UDP/TCP 需明确勾选并确认 | 公共服务选择只影响原始目标，不改变系统解析器；未增加 DoH 探针 |
| 观察与建议 | 区分返回地址、错误、取消、未执行、NXDOMAIN、TC、空响应及协议差异 | 不输出“DNS 隐私通过”，不从结果差异自动归责 VPN |
| 配置审查与副本 | SnakeYAML 2.7 安全节点解析，局部原文补丁，回读并校验变更范围 | 只审查选中的文件，没有检查客户端最终配置或实际路径 |
| 系统设置辅助 | 复制公开服务的 Private DNS 主机名，打开公开设置入口 | 由用户修改，应用不写全局 DNS 或 VPN 设置 |
| 基线与复测 | 一个当前报告、一个用户选择的运行基线；重复执行被冻结的计划 | 只保留在当前进程，单次改善不是已修复证明 |
| 对照导出 | 同时嵌入两份报告与比较结论，可选脱敏/完整 | 两份报告使用同一脱敏规则；脱敏不是绝对匿名 |

操作、精确修改范围、官方服务地址与限制见 [DNS-REPAIR.md](../../guides/DNS-REPAIR.md)。现有原始 DNS 协议能力见 [RAW-DNS.md](../../guides/RAW-DNS.md)。

## 审查关注点

### 诊断结论

新增的系统/原始 DNS 对照已限制为同一规范化域名：专业模式可以分别填写两个域名，不能把域名 A 的失败与域名 B 的成功归为系统 DNS 异常。不同域名只给出无法直接对照的提示，并有对应测试。

比较要求同运行版本、同计划且两次运行各自的观察稳定。取消、未执行、记录缺失或重复等不计为退化；NXDOMAIN、TC、空地址不计为解析可用。主要网络环境改变时不可比；仅两次间 DNS 配置变化时可对照现象，但明确不作因果归属。DNS 返回地址一致也不用于证明路径一致。

### 生命周期与证据绑定

- 修复页面为非导出 Activity，由首页进入。打开页面、选择预设和生成配置均不提交探针。
- YAML、修改计划、输入草稿和报告只在当前应用进程内保留。文件操作的 Bundle 只携带随机身份与请求码，不携带配置内容。
- 修复导出在打开文件窗口前冻结输出及原件身份；回调匹配身份和请求码，旧回调不能消费新计划。重建请求码不会复用仍可能返回的旧值。
- 基线复测沿用原始配置，包括 NETWORK 模式当时选出的数字 DNS 地址；不会静默换成后来网络的地址。每次仍需确认。
- 对照导出在取得用户选择时序列化两份报告。其后当前报告或基线变化，不改变已经批准的待导出内容；取消文件窗口会丢弃该待导出请求。

### 文件安全与隐私

输入限制为 UTF-8、256 KiB、单文档及受支持的块式映射；解析器限制深度和节点数，拒绝重复键、锚点/别名、合并及自定义标签，不构造任意 Java 对象。非目标节点与规则原文保留，输出重新解析和校验；这些是源码机制，实际测试结果见下表。

修复前还检查配置用途：发现其他应用或代理核心的标志（包括 `dns.servers`）时拒绝；缺少可识别 Mihomo 字段时只给出未确认用途的摘要，拒绝自动修复。这是保守的字段识别，不是完整 Mihomo 配置校验，也不能确认用户当前客户端版本支持所有字段。

本轮交叉审查补充了三组边界：URL fragment 按百分号解码后检查 H3/跳过证书校验参数，非法编码拒绝处理；通用或外来 YAML 不再进入自动修复；块式列表替换和末尾插入保留相邻章节注释与非目标行内注释。被替换字段内部的排版或注释可能变化，因此不承诺整份输出与原件逐字节一致。

应用不请求配置里的 URL，不上传订阅，不记录可能含原文/凭据的异常。旧 DNS 列表的预览内容隐藏；完整修复副本仍保留敏感信息，保存前会提示选择自己控制的位置。系统文件选择器允许第三方提供者；选择云盘导入可能由该提供者下载文件，选择云盘导出可能上传文件，不能把应用没有主动请求订阅 URL 扩大成整个操作绝不联网。

创建副本采用 Android `ACTION_CREATE_DOCUMENT`，另拒绝原始 URI 或相同提供者的相同文档 ID。Android 的正常创建流程避免覆盖同名文件；应用无法完整核验恶意提供者的任意别名。保存失败可能留下不完整副本。[Android SAF 文档](https://developer.android.com/training/data-storage/shared/documents-files)

### 保留的工程限制

第三方文档提供者的打开、读取和写入没有绝对时间上限；若其停滞，修复会持续占用单个工作槽，忙时不能清除或开始第二项操作。应用不会把该状态当作成功，不通过无限新建线程隐藏阻塞。此限制需要在真实提供者与设备上继续验证。

Mihomo 的路由遵循、引导解析与节点解析并非同一条配置路径。当前方案设置普通上游 DoH 和 `respect-rules`，但保留原策略分支；新增数字引导可能明文，现有规则可能 DIRECT，客户端也可能覆盖文件。源码拒绝识别到的 H3 冲突，不代表所有运行时组合已验证。[Mihomo DNS 配置](https://wiki.metacubex.one/config/dns/)

### 新依赖与本机构建

源码通过标准依赖 `org.yaml:snakeyaml:2.7` 使用 SnakeYAML，仓库仍为标准 Maven Central 配置。本次机器的 Gradle JDK 无法验证仓库 TLS 证书链，因此构建阶段使用 PowerShell 的系统证书信任通过 HTTPS 获取该模块，并与 Maven Central 发布的 `.sha256` 核对，再通过只匹配 `org.yaml` 的本地镜像初始化脚本提供给 Gradle；没有关闭 TLS 校验或修改系统证书，也没有把该机器专用镜像写入源码依赖配置。下载源为 [Maven Central 的 SnakeYAML 2.7 目录](https://repo.maven.apache.org/maven2/org/yaml/snakeyaml/2.7/)。摘要一致表示取得的文件与仓库发布摘要一致，不等于对该依赖作了独立安全审计。

### 取消失败、定位与修正

首轮 4 秒内未释放运行槽；加入限定线程栈诊断后复现。该次记录显示取消报告已发布、UDP 为 CANCELLED、TCP 未执行，清理线程已空闲，但工作线程仍停在 Android `IoBridge.poll → PlainDatagramSocketImpl.doRecv → RawDnsProbe.udp`。这支持“关闭路径返回后，UDP 接收未及时退出”的有限结论，不代表所有 Android 版本都有相同问题。详见 [修复前诊断](../../../verification/v0.3.0/device-smoke-before-udp-fix.json)。

修正为每次 UDP 接收最多等待 250 ms，回到循环检查取消、过期和原有绝对截止时间。查询仍只发送一次，不重发、不回退 TCP、不延长总预算。核心回归验证跨多个等待片段的迟延响应、总超时与 10 秒等待预算下的快速取消；原设备 4 秒断言没有放宽，最终三轮全部通过。

另修复独立发现的取消顺序风险：冻结当时阶段与观察后，先唤醒 DNS 并提交 socket 清理，再在控制器锁外采集终态快照；唯一发布和工作线程退出共同控制运行槽。四项控制器回归验证阻塞快照期间清理可启动、取消阶段不丢失、后续 TCP 不启动及晚取消不改写已冻结的正常结果。该风险与上述 UDP 等待问题分别记录，不把它冒称为首轮失败根因。

## 尚未验证

没有据此完成实体手机、真实代理客户端导入及最终配置、公共 DoH/DoT 可达性、DNS 线上去向、Wi-Fi/蜂窝切换、跨应用流量、断线保护或外层 IPv6 路径验收。本工具不占用 VPN、不装 CA、不控制其他代理客户端，也没有自动重试或后台定时探测。

下一步的有效验收应在保留原配置和基线的前提下，导入副本、查看客户端最终配置，并用受控解析器或网关日志关联请求。只有应用内“返回地址”或离线测试通过，不能升级为“修复 DNS 泄露”结论。
