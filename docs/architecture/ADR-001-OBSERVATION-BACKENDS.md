# ADR-001：保留代理环境的多后端观测

状态：Proposed / Draft（下一实现提案）；2026-10-23；[文档导航](../README.md)。既有默认普通权限、不自动接管VPN的决定继续有效；下列新接口与数据模型尚未实现。

## 问题与候选

用户要求深入定位DNS/TLS/代理问题，并希望必要时覆盖更多设备流量。现有App只有本应用观察，不能取得核心规则/链路；直接加入抓包VPN又可能改变正在被测的VPN。

| 候选 | 优点 | 代价/缺口 | 决策 |
|---|---|---|---|
| 仅继续增加公网探针 | 输入少、复用现有代码 | 不能解决核心规则与外层路径的观测缺口 | 保留基础能力，避免无目的扩大目标 |
| 默认自有VPN捕获 | 自身TUN包可见 | 替换原VPN、需要转发、仍无自动HTTPS明文 | 不作为默认下一步；保留独立研究 |
| 普通探针＋代理只读协同 | 可补核心连接与规则，不占VPN | API可能关闭、凭据敏感、关联/短连接缺口 | 推荐下一纵向实现 |
| ADB/Root/外部网关 | 需要时可增加独立观察位置 | 部署/授权/功耗与覆盖复杂 | 插拔增强后端，不作为基础必需 |

依据及不同来源可靠性见[能力矩阵](CAPABILITY-MATRIX.md)。选择依据是补齐特定证据，不能把接口读通作为代理全局正确的证明。

## 模块与接口边界

沿用现有探针，增加后端适配接口：能力预检、受限计划执行、取消、观测输出。证据存储/关联与诊断规则从UI解耦；修复动作单独注册写能力。不是所有后端都必须提供包、UID、证书或相同字段；缺失和数据丢失是契约的一部分。

## 下一最小实现：一次可追溯的代理协同实验

前置：修正报告版本来源；为两种现有报告增加兼容外层，不能直接改写旧schema。以[事件草案](EVENT-CONTRACT-DRAFT.md)作为实现前讨论基线。

纵向流程：用户指定控制端点/认证 → 有界/version能力预检 → 明确是否允许/connections短时采样 → 一个受控测试连接 → 展示候选核心记录、规则和关联依据 → 脱敏导出。无API/拒绝授权时网站诊断仍能运行，结果标能力缺失。

建议初始预算：控制响应256KiB、每次3秒、每轮总15秒、最多3次快照；以上是待实现上限，不是现有App参数。默认不请求规则全集/节点配置、不启动日志长流、不后台轮询。要证明长连接关联，需先实现并验证本应用本地socket元组的采集；当前WebsiteDiagnostics只记候选对端，不能据此直接确认跨后端同一连接。

传输选择必须预检：当前Manifest禁明文HTTP，许多控制口只有HTTP；不能为接入API全局开放明文。首版可接受受信HTTPS端点或版本化离线摘录。若后续支持本机HTTP，需要单独限定数字回环、禁止代理/重定向逃逸、验证Android网络安全策略与服务身份，不能自动暴露控制口到LAN。TLS不可信时不跳过校验。

## 验收与负例

授权与撤销按能力分别管理：普通网络权限由清单声明，仍需明确主动测试计划；代理端点和Secret由用户提供且仅进内存，断开协同清除认证与待采样任务；ADB信任由系统/主机管理，退出时关闭本工具建立的转发和服务，不声称已撤销所有主机授权；VPN需说明会替换现有服务并提供停止/恢复步骤；Root与外部捕获按具体范围授权、停止采集并核对资源退出。拒绝增强能力时继续基础模式，撤销后保留已冻结的脱敏结果并阻止迟到证据覆盖。以上是后续适配器要求，当前App未实现这些增强入口。

- 合成API：401/403/404、慢响应、非JSON、超大、缺字段、重定向、重复ID、连接消失、核心版本/兼容层差异。
- 保证没有写路由、测速、healthcheck或dns/query调用；密钥不出现在日志/报告/URL；未开API不扫描端口。
- 两条相似连接或时钟不明时返回AMBIGUOUS/UNRESOLVED；不靠同IP/近时间确认。
- 真机只在用户提供确切端点后进行受控长连接对照；记录代理模式、版本、采样间隔、丢失与服务端标识。只有API字段与主动探针的关联被验证后，才提供“该连接命中此规则”的确定性表述。
- 取消、换网、预算、拒绝与进程退出不产生迟到覆盖；基础模式保留。

## 未决风险与重新评估条件

真实客户端API不可用时，先做导出摘录适配或ADB协作；若问题明确涉及核心未见的其他App流量，再评估独立VPN/Root/网关。没有新的观察位置或可靠关联时不增加“安全评分”。外部捕获若改变路由，必须作为另一实验条件保存。每个后端需按确切实现/版本重验，不能复用“Clash兼容”标签代替行为测试。
