## 后续优先级建议

下一步优先：在实体 Android 设备和受控 HTTPS / DNS 端点完成正常/错误/取消/旋转/导出验收，验证 VPN 开关及分应用范围。模拟器回环不替代这一步。

原始 DNS 的 UDP/TCP 与数字 IPv4/IPv6 目标已在 0.2.0 实现；HTTPS 强制地址族与物理出口证明仍未实现。每种协议独立记录状态和错误，不从 TCP 外推 UDP。

阶段四：网关、核心与端点日志按明确关联依据对照；本版已实现用户声明API的只读快照，但尚无自动关联。时间窗口和相同IP单独只能形成候选，不能确定属于同一请求；记录盲区、丢包、时钟误差，再评价 DNS 保密和严格代理故障策略。

阶段五：如确需全机抓包，单独评估 root/网关/系统权限与许可路线。VpnService 抓包通常与被测 VPN 冲突，不能悄悄替换被测对象。

任何阶段的“符合”都只对列明的设备、配置、协议、目标、时间窗口和证据成立。
