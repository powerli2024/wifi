# 原始 DNS：指定目标的 UDP / TCP 对照

> 类型：操作指南；状态：Active；范围：0.6.0现状或明确标注的目标要求；维护：项目维护者；核对：2026-10-23。
> [文档导航](../README.md) · [当前验证](../testing/CURRENT-STATUS.md)。文内反引号文件路径若无说明均相对项目根。

本功能只发送本应用的实验请求，不占用 Android VPN 接口。UDP 与 TCP 分别执行，使用同一个明确配置的数字目标、端口、查询域名和记录类型；默认每项一次；专业页可明确允许超时后追加一次并保留首次失败，没有 TCP 回退、扫描或后台运行。

## 手机上的最短操作

1. 保持待验证代理的设置，确认该代理是否将本工具纳入转发。
2. 若仅测试 DNS，关闭 HTTPS 与系统 DNS；勾选原始 DNS UDP、TCP 或两者。
3. 填入你拥有或获准测试的解析器数字 IP；支持 IPv4 和无作用域的 IPv6，不接受服务器域名，避免隐式引导解析。端口默认 53，可用于自控非标准端口实验。
4. 输入受控测试域名。建议每次用新的随机标签，并在自控权威域名上设置匹配记录；程序不会自动添加标签或修改你确认的域名。
5. 选择 A 或 AAAA，检查确认框中的目标、端口、域名和两种协议，再开始。
6. 导出 JSON，与自控解析器、网关和代理日志按域名、协议、事务 ID 及运行时间窗口关联。事务 ID 只有 16 位，不是全局唯一标识。

默认每项原始 DNS 探针使用 8 秒绝对截止，包含连接及分段读取；启用它们后整次运行的证据接收/终态发布预算为 60 秒。混跑 HTTPS 时，平台资源清理和运行槽占用仍可能超过该预算。取消先发布终态并关闭活动 socket；尚未开始的协议保留“未执行”。UDP 截断不会隐式触发 TCP；只有用户预先选中 TCP，才会独立查询它。

## 结果怎么读

| 观察 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 取得匹配问题、事务 ID 的响应 | 本次 socket 收到了可解析且与请求对应的 DNS 报文 | 指定解析器身份可信、没有 VPN 接管、物理链路走向 |
| 响应码 0、地址非空 | 响应含目标或其 CNAME 链上的对应类型地址 | 结果正确、DNSSEC 验证通过、DNS 保密 |
| NXDOMAIN（3） | 对端声明该域名不存在 | 网络安全或发生泄露 |
| 截断标记 TC | 对端声明响应不完整；本工具不把地址当完整结果 | TCP 同样可达或安全 |
| 超时、IO 错误、取消 | 未取得本项完整证据 | 代理阻断正确、没有泄露 |
| 数字 IPv6 目标 | 请求的 socket 目标为 IPv6 字面地址 | VPN 外层、运营商或整个代理链使用 IPv6 |
| AAAA 响应 | 返回的是 IPv6 地址记录 | 承载该 DNS 查询的连接使用 IPv6 |

原始查询本身没有 DNS 加密。VPN 可以接管并将它封装在隧道内；也可能将它改送另一解析器。因此，“设置了某个服务器”或“成功收到回答”均不等于知道物理出口。要判断泄露，先声明预期策略，再观察实际出口。

## 解析与资源边界

请求采用单问题标准 DNS，无 EDNS 扩展请求。响应上限 4096 字节；TCP 先验证长度前缀，读取使用绝对截止，避免慢速分段无限延长等待。响应校验事务 ID、QR、opcode、问题名、类型、类、资源长度、压缩指针边界与循环；区分扩展 RCODE。只提取 answer 区与问题/CNAME 链对应的 A 或 AAAA。

这是有限诊断解析器，不是完整递归解析器或 DNSSEC 验证器。未知 RR 的 RDATA 不作域名解码，后续压缩指针若指向这种尚未登记的域名边界，可能被保守拒绝为 `INVALID_DNS`。超大报文、未知编码或不支持的结构也不能被解释为“代理不安全”。

JSON schema 2 新增 `rawDnsConfig`、`rawDns`、`evidenceBudgetMillis`。默认脱敏目标地址、域名和返回地址，保留协议、响应码、耗时与错误；每项隐私判定最多为“观察不足”，未启动则为“未执行”。HTTPS 回显端点契约仍为 v1，不随报告 schema 升级。

协议依据：[RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html)、[RFC 6891](https://www.rfc-editor.org/rfc/rfc6891.html)。未复制其他代理客户端代码。

## 两个入口的预算

本指南手工数字目标、默认8秒与可选限定重试适用于专业入口。0.6.0深度诊断按当前DNS执行A/AAAA×UDP/TCP四项，每项最多4秒、各一次，受整体60秒约束。它不提供全设备IPv6路径或DNS泄露证明。
