# DNS 检查、配置副本与复测

> 类型：操作指南；状态：Active；范围：0.6.0现状或明确标注的目标要求；维护：项目维护者；核对：2026-10-23。
> [文档导航](../README.md) · [当前验证](../testing/CURRENT-STATUS.md)。文内反引号文件路径若无说明均相对项目根。

适用版本：0.5.0。实现及验证边界见 [审查记录](../releases/0.5.0/REVIEW.md)。本轮不运行模拟器，装机操作见 [实测指南](../releases/0.5.0/TEST-GUIDE.md)。

本工具帮助你记录本应用的解析结果、审查一份配置、生成可检查的修改副本。保存文件不等于代理客户端已经应用；返回地址不等于全机 DNS 没有泄露。手机系统 DNS 与代理客户端内置 DNS 是两条需要分别核对的配置路径。

## 先取得修改前的观察

1. 保持当前网络和 VPN 状态，点击“开始快速检查”，阅读目标后确认。默认只让 Android 解析 `example.com`，不需要填写 HTTPS 服务地址。
2. 检查完成后，点击“保存当前结果为对照基线”。基线仅保留在当前应用进程；需要长期保留时另外导出 JSON。
3. 若需要 UDP/TCP 对照，先明确勾选“同时检查原始 DNS”，再选择当前网络配置的解析器或公共服务。该选择只影响原始 DNS 探针，不会改变系统解析器。
4. 一次只调整一项设置，再用“按基线相同计划复测”。此按钮保留原域名、协议和数字目标，不会随新网络重新选择 DNS 地址。

当前网络显示的 DNS 地址可能是 VPN 虚拟地址；系统解析可能使用缓存。原始 UDP/TCP 查询是明文，即使系统显示 Private DNS 已启用也不会自动转换成加密查询。默认没有附加尝试，不回退 TCP；专业页可明确启用限定错误最多两次，全部计入原总预算并逐次记录。需要自定义目标、AAAA 或 HTTPS 来源回显时，进入“测试”。协议范围见 [RAW-DNS.md](RAW-DNS.md)。

`example.com` 是 IANA 保留的示例域名。快速检查不固定其返回 IP，也不访问其网页；单次查询不代表所有域名和业务都可用。[IANA 示例域名说明](https://www.iana.org/help/example-domains)

## 选择公共服务

| 服务 | 原始 DNS 数字目标 | 配置副本使用的 DoH 地址 | Android Private DNS 主机名 |
|---|---|---|---|
| Cloudflare 标准服务 | `1.1.1.1` | `https://cloudflare-dns.com/dns-query` | `one.one.one.one` |
| Quad9 威胁阻断服务 | `9.9.9.9` | `https://dns.quad9.net/dns-query` | `dns.quad9.net` |
| Google Public DNS | `8.8.8.8` | `https://dns.google/dns-query` | `dns.google` |

这是少量固定预设，不是测速排名或可达性保证。Quad9 的该地址有威胁阻断策略，结果差异不能直接归为代理故障。这里的 DoH 地址用于配置生成；应用自身尚未实现 DoH 网络探针。公共服务会处理实际发送给它的查询。

地址及用途来源：[Cloudflare 地址](https://developers.cloudflare.com/1.1.1.1/ip-addresses/)、[Cloudflare DoH](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/)、[Cloudflare DoT](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-tls/)、[Quad9 服务表](https://docs.quad9.net/services/)、[Google 配置说明](https://developers.google.com/speed/public-dns/docs/using)、[Google DoH](https://developers.google.com/speed/public-dns/docs/doh)。

## 修复 Mihomo / Clash.Meta 配置

可先用 [纯示例文件](../../fixtures/mihomo-dns-example.yaml) 练习“选择 → 预览 → 保存副本”。示例没有节点或订阅，规则故意为 DIRECT；不能用它替换日常代理配置或证明代理隐私。

1. 在修改前保存观察基线，并保留客户端当前可用配置。将你有权处理的完整 YAML 导出到自己控制的位置。
2. 打开“修复中心”，通过系统文件窗口选择自己控制的本地 YAML。应用只读取你选中的内容，不访问其中的订阅、节点或规则集 URL。文件窗口也可显示云盘；选择它时，文件提供者可能自行下载内容。
3. 选择服务，生成修改预览。阅读每项修改与未覆盖范围；遇到不支持的结构时停止自动修改，保留原件。
4. 点击“保存修复副本”，在系统文件窗口创建新文件。完整 YAML 保留原有节点密码和订阅地址，不能当作脱敏报告分享。
5. 在代理客户端中将副本作为本地配置导入，使用客户端自身的校验功能。检查全局 DNS 覆盖、追加系统 DNS、订阅更新和配置混合选项；它们可能重新改变生效内容。
6. 确认客户端成功加载后，返回首页，按基线相同计划复测。若导入或解析失败，恢复原配置，不要把失败副本作为唯一可用配置。

0.5.0 保存后尝试读回文件：摘要与字节数一致且结构检查通过才显示“副本已读回核对”。不可读显示“已写入，内容未核实”；截断/替换/超限显示失败。仅已核对副本可记录“我已在客户端导入此副本”，这仍是用户声明。生成预览时关联当前基线；后续更换基线需要重新生成，避免误配修改前的记录。

自动方案只处理下列五类字段。已有合法且非空的引导/节点解析器列表会保留，并不承诺升级其加密方式。

| 字段 | 自动方案 |
|---|---|
| `dns.enable` | 明确设为 `true` |
| `dns.nameserver` | 替换为所选服务的 DoH |
| `dns.default-nameserver` | 保留受支持的非空原列表；缺失、空值或空列表时补充所选数字 IPv4 |
| `dns.proxy-server-nameserver` | 保留受支持的非空原列表；缺失、空值或空列表时补充所选 DoH |
| `dns.respect-rules` | 明确设为 `true` |

新增的数字引导地址使用明文 DNS。`respect-rules` 遵守现有路由，规则仍可选择 DIRECT；节点域名解析及现有 `nameserver-policy`、`fallback`、`direct-nameserver` 等分支需要单独检查。方案不猜测代理组名称，不改 TUN、IPv6、Fake-IP、节点、规则或监听地址。字段含义参见 [Mihomo DNS 文档](https://wiki.metacubex.one/config/dns/)；这里列出的具体修改范围是本工具的实现选择。

修复器通过 YAML 节点定位局部文本，再重新解析输出并核对非目标字段。它不会对整份配置重新序列化；非 DNS 的凭据和规则原文保留。被替换字段内部的注释或格式可能变化，应阅读副本；保存时选择云盘也可能由文件提供者上传完整内容。源文件 SHA-256 用于核对读入内容，不是签名或“配置安全”证明。

## 调整 Android 系统 Private DNS

1. 先记录当前模式与主机名，并保存修改前的观察基线。
2. 在修复中心复制所选服务的 Private DNS **主机名**。此步骤不修改系统设置。
3. 点击网络设置入口，在设备设置中找到 Private DNS；厂商菜单位置可能不同。需要时手动选择提供商主机名模式并粘贴，不能把 DoH URL 填入主机名栏。
4. 返回应用，手动确认后按原计划复测。如果网络不支持该服务或解析出现故障，恢复先前记录的模式。

应用只使用公开的网络/VPN 设置入口，没有修改全局设置的权限或隐藏 API。VPN 客户端可能另有 DNS 策略；系统快照的 Private DNS 状态不能代表所有应用请求。Android 对该状态及主机名的定义见 [LinkProperties](https://developer.android.com/reference/android/net/LinkProperties#isPrivateDnsActive())；Google 的 [Android 配置步骤](https://developers.google.com/speed/public-dns/docs/using)可作为主机名模式参考。

## 如何读诊断和对照

| 观察 | 能说什么 | 不能据此断定 |
|---|---|---|
| 返回有效地址 | 本次探针取得地址 | 地址可连接、网站可用、解析器身份已认证或无泄露 |
| NXDOMAIN | 收到名称不存在的响应 | 此域名已经成功解析到地址 |
| NOERROR 但无地址，或 TC 截断 | 保留响应与标记，未取得完整的地址结果 | 解析可用或隐私验证通过 |
| UDP 与 TCP 结果不同 | 两种协议本次表现不同，需要受控复查 | 一定是 VPN、运营商或防火墙导致 |
| 系统解析与原始 DNS 不同 | 仅在查询域名相同时提示核查解析方式 | 返回同一 IP 就走同一路径，或不同 IP 就有泄露 |
| Private DNS 为 `false` / 未知 | 当前系统快照的状态 | 明文查询已实际发生或已发现泄露 |
| 可用性观察改善 | 相同计划下，本次取得了先前未取得的结果 | 某项操作已修复问题，或全机已安全 |

演示、取消、未执行、记录缺失、运行期间网络变化，以及版本/目标/主要网络条件不同时，比较会保守标为不可比。仅两次之间 DNS 设置发生变化时，可保留相同探针的观察对照，但不作因果归属。旧记录的通用 DNS_FAILURE 无法区分具体原因；新版仅按实际取得的诊断码解释，不推断缺失值。

两报告对照导出同时保存完整的“修改前”和“修改后”报告结构及比较说明。默认脱敏；仍包含时间、Android API、状态、数量等信息，不保证绝对匿名。进程结束会丢失内存基线；当前版本不能将导出的历史报告重新导入为基线。

## 兼容范围与失败处理

- 仅支持 UTF-8、最多 256 KiB、单文档、块式根映射与块式 `dns` 的 Mihomo YAML。大小限制根据实际读取字节检查，不依赖文件提供者报告的长度。没有 `dns` 块时可以补充；这不代表原配置必然有漏洞。
- 拒绝重复键、锚点/别名、合并键、自定义标签、复杂映射键、超过 40 层或 20,000 个节点等输入；不是通用 YAML 编辑器。DNS H3 与本方案存在冲突时要求人工处理；URL 附加参数在百分号解码后检查，不能安全解析的编码也会拒绝。
- 检测到其他应用/核心的字段或 `dns.servers` 时拒绝生成副本；没有可识别的 Mihomo 字段时仅给出未确认用途的摘要。字段识别并非完整配置校验，含节点的片段即使能通过此识别，也不代表它是可直接导入的完整配置。
- 不支持将 sing-box/Hiddify JSON、订阅链接、节点片段或任意旧 Clash 内核配置视为已验证兼容。应核对实际客户端与内核版本，再使用客户端自身的配置校验。
- 导出采用 Android 创建文档流程，并检查与原始 URI/文档 ID 的冲突。该保护以合规文件提供者为前提；不保证能识别恶意提供者返回的任意别名。[Android SAF 契约](https://developer.android.com/training/data-storage/shared/documents-files)
- 保存报错可能留下不完整副本，应创建新文件重试。第三方文档提供者可能阻塞读取/写入；当前会保留单个工作槽等待，不宣称已完成，也不会无限新建线程。必要时退出应用进程并重新选择可信的本地提供者。
- 旋转保留进程内状态；进程丢失后旧文件窗口结果不能写出新配置。清除内存配置不会删除已经导出的文件。

本版本尚未据此完成真实代理客户端导入、实体手机 DNS 路径、断线保护或全机泄露验收。对线上路径的结论仍需受控解析器/网关日志或抓包与本次请求关联。测试状态见 [V0.5.0-REVIEW.md](../releases/0.5.0/REVIEW.md)。

## 当前适用范围

本指南继续适用于0.6.0保留的专业诊断与修复链。基线/比较使用RunReport，网站深度诊断DeepReport尚未接入；配置文件读回不等于代理客户端运行配置生效。当前实测范围从文档总入口的验证状态查看。
