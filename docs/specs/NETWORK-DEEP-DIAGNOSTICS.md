## 自动执行流程

入口为“开始网站与网络诊断”，默认填写 https://chatgpt.com/，支持自定义 HTTPS 完整网址。将用户原文 cahtgpt.com 按 ChatGPT 意图选择预设；程序不纠正自定义域名。打开界面不发送请求，点击开始后运行确认的固定计划。

1. 采集 Android 可见网络：默认/进程绑定网络、可见网络清单、承载、系统能力、接口、地址/前缀、路由/网关、DNS、搜索域、MTU、Private DNS、HTTP代理/PAC配置、系统带宽估计及可得信号值。缺失字段记录原因。
2. 手机内置实验：临时回环 TCP/HTTP 正常回应、受控读取超时、受控拒绝连接。只使用数字回环地址，结束关闭服务，无需电脑、Python、root 或第二个 VPN。
3. 按正常默认网络和系统代理选择访问网址，记录 DNS、连接/代理隧道、TLS、HTTP 和正文读取。保留正常证书信任与主机名校验。
4. 暂时性连接/等待错误自动复核一次相同网址，保留首次失败；证书错误、HTTP状态、输入错误不靠反复请求掩盖。
5. 启用扩展DNS时，自动取确认时当前网络第一个数字DNS，对网站域名执行 A/AAAA × UDP/TCP 四项，每项最多4秒。该模块会产生明文DNS，保持明确选择，不静默套用公共解析器。
6. 重采网络画像，生成定位、冲突说明、下一步动作和JSON。网络条件改变则停止后续实验，保留已完成结果。

## 0.7.0 报告交互

深度诊断仍是“概览 / 测试 / 修复”下的子页。顶部 MaterialToolbar 保留返回与导出，导出在报告可用且没有待处理导出时启用，滚动到详情后仍可访问。首张卡运行时展示当前阶段，完成后展示本次主要定位：停止原因优先，其次网站摘要，再次本机检查摘要。HTTP 代理解析说明不会盖过网站 TLS 或连接故障。

结果前提供单报告导出、保存基线、按原计划复测和双报告导出。DNS / 连接 / TLS / HTTP / 正文用五行显示状态与耗时；多次尝试保留首次阶段，注明复核次数。HTTP 状态、TLS 版本和总耗时作为摘要补充，未观测与失败使用不同文字。

定位依据、网站完整证据、Android 网络画像、本机受控实验、原始 DNS 对照和比较条件默认折叠，用户可逐项展开。展开只读取已冻结报告，不触发新采集。展开状态在同份报告旋转后保留，新报告恢复折叠；状态 Bundle 只保存分组标识和运行 ID，不保存网址、查询参数或网络画像。

保留网址输入、代理状态声明及原始 DNS 明文确认；数字 IP 网址与域名 DNS 对照的冲突继续就地提示。界面与确认回调均检查深度诊断、专业测试、网站资源释放和代理只读协同的忙碌状态。打开“代理只读协同”入口只导航；其采集另行确认。

## 0.7.0 深度基线与复测

此流程属于 `DeepReport`，与既有专业测试 `RunReport` 基线分别管理；没有实现跨两种报告的统一基线。

1. 一次计划全部取得终态后，可以明确确认“保存本次为基线”。确定的网络失败也能成为基线；取消、换网、缺少可核对网络画像、本机实验未结束或原始 DNS 缺测会阻止保存，并显示原因。替换已有基线同样需要明确动作。
2. 基线仅在应用进程中保留报告和原完整计划，包括网址路径/查询参数、预算、代理声明和原始 DNS 数字目标。旋转不丢失；进程丢失后不恢复或猜测。基线留档使用导出，完整导出仍省略 URL 路径与参数。
3. “按基线原计划复测”优先使用基线；没有基线时可复用当前完整报告的计划。再次确认展示原目标、预算及明文 DNS 目标，随后执行。当前输入框修改不替换冻结计划，当前 DNS 配置变化也不静默替换原始 DNS 目标。
4. 新报告完成后自动生成对照。版本、网址/预算、代理声明、原始 DNS 目标及默认网络/VPN/HTTP 代理/绑定/链路等条件用于可比性检查；系统 DNS 或 Private DNS 改变作为显式说明保留。条件冲突时显示具体阻断项，两份报告仍可导出。
5. 对照只描述观察变化，例如网站首次结果、阶段耗时、DNS 回答和本机检查。后续尝试成功不覆盖首次失败，单次变快不等于稳定改善，也不把变化宣告为因果修复或无 DNS 泄露。

“导出基线与本次对照 JSON”产生 `NETWORK_DEEP_COMPARISON`，内含两份 `NETWORK_DEEP_DIAGNOSTICS` 与比较条件。它与单报告导出共用唯一票据/请求码：打开系统保存窗口前冻结载荷，旋转或清除当前基线不改变已确认载荷；旧回调不能消耗新票据，丢失原载荷时不得换成新的报告写入旧位置。

## 层级与处理动作

| 层级 | 取得的信息 | 处理方向 |
|---|---|---|
| Android环境 | 承载、VPN、系统代理、链路、路由、验证状态 | 无默认网络先查连接；用户称代理开但App不见VPN，核对VPN/TUN和分应用范围 |
| DNS | 请求解析事件、候选地址/族、耗时和错误；可选原始查询 | 原始可响应而系统调用失败，查系统/客户端解析接管；NXDOMAIN先核对域名 |
| 连接 | 候选连接、socket对端、显式代理类型与耗时 | 定位连接/代理隧道阶段；代理socket对端不等于源站 |
| TLS | 验证结果、版本、密码套件、证书到期、阶段错误 | 查设备时间、目标主机、证书/拦截配置；不提供忽略证书的修复 |
| HTTP | 协议/状态/跳转来源和首部阶段 | 403/429归为服务响应线索，保留连接/TLS已成功事实 |
| 正文 | 有界读取字节数、截断、读取失败 | 达上限为部分读取；正文超时与首部成功同时保留 |
| 本机实验 | 正常/超时/拒连是否符合预期 | 验证本工具运行环境，不能代替网站TLS或外网检查 |

本版连接阶段从开始连接计到进入TLS，可能包含代理CONNECT，因此不是纯TCP握手RTT；OkHttp原始connectStart/connectEnd区间则包含TLS，二者不能混用。无法单独拆出的隧道时间不伪造。参考锁定版本 [OkHttp EventListener](https://raw.githubusercontent.com/square/okhttp/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/EventListener.kt)。

系统链路字段用于补全环境，带宽估计不是吞吐测速。参考 [Android LinkProperties](https://developer.android.com/reference/android/net/LinkProperties)。用户声明、系统状态与本次请求事件分开存储，不互相冒充。首次失败、复核成功表示现象不稳定，不能展示全部通过。

## 实现与资源约束

网站使用 OkHttp 4.12.0 记录HTTP事件，底层使用Android DNS、Socket和平台TLS，不内置Python/Node/浏览器内核。GET不携带浏览器Cookie/Authorization、不执行脚本、不自动跳转；正文最多读取16KiB，只计数不保存。完整报告也不保存URL路径和查询参数。

网站单次预算15秒、总预算30秒，最多两次；整体诊断60秒，本机实验默认3秒。超时冻结证据并取消；若系统DNS不响应取消，旧工作保留唯一槽位，不能无限创建线程绕开。网络变化后不在新网络继续同一实验。

新增独立 NETWORK_DEEP_DIAGNOSTICS 报告，包含前后画像、本机实验、网站逐次结果、原始DNS、用户声明与停止原因。默认脱敏；用户可选完整本地导出。无后台采集或上传，进程内保留。原 schema 2 DNS/回显报告和 /v1/echo 严格契约保留。

系统设置修改由用户确认，应用提供VPN/网络设置入口及既有配置副本流程。诊断不关闭验证、不替换VPN、不扫局域网、不读取其他App私有数据、不安装CA。

## 服务完整性与下一阶段

ChatGPT还涉及认证、静态内容、上传等多个域名及部分WebSocket连接。因此入口GET成功不等于登录/对话/上传全可用；后续引入有版本的服务依赖模板，按需展开，不后台遍历域名。[OpenAI网络建议](https://help.openai.com/en/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps)

下一阶段：地址族定向对照、独立DoH/DoT、客户端日志/生效回执、受控TLS本机实验、WebSocket/HTTP3。DNS泄露与整机覆盖仍需关联外层证据；工具应先自动取得已有能力范围内的信息，再指出缺失的具体证据和补测方式。

0.7.0 的折叠布局、基线与复测已有针对离线注入后端的框架测试用例；是否执行通过以独立验证记录为准。它们不能替代新版本真机上的字体、TalkBack、横屏、文件提供者和真实代理路径检查。
