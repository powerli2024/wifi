## 1. 目标及需要纠正的思路

目标不是“尽可能多地发请求，再挑选最可信的结果”，而是：**针对一个明确的问题，在受控成本和隐私边界内取得能区分候选解释的证据，并完整保留尚不能回答的部分。**

| 容易采用的做法 | 具体问题 | 本规格的替代约束 |
|---|---|---|
| 同时检查所有协议、所有 DNS、所有出口服务 | 改变缓存、连接复用及流量负载；增加第三方披露；不同目标不能互相替代 | 先声明待回答问题，再选择最小必要探针；扩展目标必须产生新计划 |
| 多个来源同意就提高安全分数 | 多个接口可能来自同一递归解析器、同一平台 API、同一服务商或相同缓存 | 记录观察位置和共同依赖；没有独立性依据时只记“重复观察” |
| 结果冲突时重试到一致 | 会掩盖间歇性错误、切网、缓存和策略差异 | 保存全部尝试与顺序；稳定性、可比性和冲突各自报告 |
| 用更换 DNS、切为 TCP、关闭 Private DNS 来“修好”测试 | 修改了被测条件；通过结果不能说明原配置问题已解决 | 建立新实验，保留原计划、变更项和失败记录 |
| 只要没有观察到泄露就给绿色通过 | 观测点可能看不到蜂窝、IPv6、VPN 外层、其他应用或加密 DNS | 将可达性、策略匹配与覆盖缺口分开；不输出全机安全总分 |

允许增加采集手段，但每一种都必须说明：新增信息是什么、能排除哪一种解释、有哪些共同依赖、会发送什么数据、以及何时停止。

## 3. 来源与能力矩阵

状态含义：**当前**＝源码有实现；**拟新增**＝已确认规划中尚待实施；**外部依赖**＝还需用户提供设备、服务、访问权或日志；**不能证明**＝即使该项成功也不能推出的结论。当前能力仍需按目标设备验证。

| 来源/方法 | 状态、前提 | 可以形成的直接观察 | 主要缺口与不能证明的内容 |
|---|---|---|---|
| 默认网络快照及回调 | 当前；应用可读取网络状态 | 本应用默认网络标识、能力和配置在何时被观察到；回调是否可用 | 不提供所有应用流量；前后相同不保证中间没有漏记变化；VPN 图标不等于请求走代理 |
| 系统 DNS API | 当前；API 29+，域名有效 | 地址、完成/取消/错误；新记录中的回调阶段与数值错误信息 | 实际递归服务器、命中缓存、线上协议、完整 A/AAAA 子查询过程未知；rcode、errno、resolver code 不能混用 |
| raw UDP/TCP DNS | 当前；明确选择数字目标、端口、域名和记录类型 | 每种协议独立的响应码、TC、地址、超时/错误；本应用的指定目标 | 应用层明文；可能被 VPN/网关接管；回复源匹配不能认证解析器；UDP 53 成功不等于任意 UDP 可用 |
| HTTPS 来源回显 | 当前；用户提供兼容端点、独立预期 IP，并确认信任 | TLS/HTTP/格式验证和本次 requestId 归属；服务端声明的来源地址是否在指定集合 | 没有预期 IP 或信任时不判匹配；匹配只限该请求，不外推 DNS、QUIC、其他应用 |
| Private DNS 快照 | 当前；LinkProperties 可用 | 本网络的活动状态及可得主机名 | 没有验证所有应用实际协议；false 也不证明 VPN 没有自己的加密 DNS |
| 本应用 DoH / DoT 查询 | 拟新增，默认关闭；独立协议实现、TLS 验证和引导方案 | 本应用与该加密 DNS 服务的一次协议交换；握手、DNS 结果与失败阶段 | 加密不等于经过代理；引导、路由和其他 DNS 分支仍可能直连；不能验证 Clash 原 App 的 DoH 实现 |
| IPv6 专项 | 当前仅数字 IPv6 raw 目标/AAAA/部分地址观察；强制地址族 HTTPS 拟新增 | 现有记录可区分“请求的目标字面地址族”与“返回记录类型” | AAAA、IPv6 回显、VPN 内层 IPv6 均不证明物理外层走 IPv6；NAT64/代理转换需另外记录 |
| 任意 UDP、QUIC、STUN | 尚未实现；受控服务、独立协议库与资源预算 | 将来可记录各协议自己的握手/交换，而非借用 TCP 成功 | QUIC 是基于 UDP 的独立协议；不能由 raw DNS 或 HTTPS 成功代替；STUN 地址也不是全机路由证明 |
| 受控权威 DNS 日志 | 外部依赖，拟新增导入；用户控制委派域和日志 | 某个精确问题在权威侧的时间、类型及发来查询的递归侧地址 | 权威看到的通常是递归侧，不是手机源 IP；不能单独证明手机到递归侧是否加密或走 VPN |
| 受控递归 DNS / HTTPS 服务日志 | 外部依赖，拟新增导入 | 对应请求、服务身份、接收时间及服务端可见连接信息 | 服务方可能与回显同源；日志缺失可能是缓存、保留策略或丢失；不能自动代表所有路径 |
| 网关/镜像口/受控接入点抓包 | 外部依赖，拟新增导入；明确接口和授权 | 在被覆盖接口和时间窗出现的匹配数据包、目的地、外层协议 | 可能看不到蜂窝、旁路接口或 VPN 内层；看不到明文查询不等于没有查询；必须记录捕获盲区 |
| 客户端配置文件 | 当前有受限 Mihomo 文件审查；实际运行信息未接入 | 所选文件内容、修复预览和副本 | 文件不等于最终生效配置；订阅、全局覆盖、客户端版本和运行状态可能改变含义 |
| 客户端只读接口/日志 | 拟新增，默认关闭；用户明确提供已知客户端接口或导出 | 核心版本、运行配置摘要、日志中的规则命中/连接记录 | 不扫描端口、不猜控制密码；核心自述不等于独立外层观测；读接口也可能产生额外网络流量 |
| root / ADB / 管理设备等特权采集 | 仅作为可选外部路线，尚未实现；按设备和权限单独设计 | 在授权范围内补充接口/进程/包的观察 | 普通 App 不具备这些能力；root、ADB 或管理身份不保证所有接口、OEM 或 SELinux 条件可用 |
| 其他应用/全机行为 | 当前不支持 | 用户另行控制的测试 App 可为它自己的请求提供证据 | 不能通过本工具成功推断所有 App；浏览器内置 DoH/WebRTC 必须独立测试 |

默认网络回调针对应用的默认网络，该网络可以是适用于它的 VPN；它不是全机逐流量审计 API。[ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager#registerDefaultNetworkCallback(android.net.ConnectivityManager.NetworkCallback)) 普通 App 也不能默认读取另一 App 的私有数据。[Android 应用沙箱](https://source.android.com/docs/security/app-sandbox)

加密 DNS 的拟实现分别依据 [DoH RFC 8484](https://datatracker.ietf.org/doc/html/rfc8484) 和 [DoT RFC 7858](https://www.rfc-editor.org/rfc/rfc7858.html)；只把协议保护范围用于对应连接，不扩展为代理路由保证。QUIC 必须独立规划，不能用 UDP DNS 代测。[QUIC RFC 9000](https://www.rfc-editor.org/rfc/rfc9000.html)

## 4. 默认不改变被测环境

1. 保持普通应用、默认网络请求的基本模式；默认不建立本工具的 VpnService，不启动其他抓包 VPN，不停止被测 Clash/FlClash。
2. 同一用户/配置文件只有一个活动 VPN service；新 service 会停止既有 service。把抓包 VPN 换上去，再经其内置上游代理转发，测试对象已经改变，不能写成验证了原客户端。[Android VPN 指南](https://developer.android.com/develop/connectivity/vpn)
3. 不自动调用 `bindProcessToNetwork`、`Network.bindSocket` 来寻求“成功路径”。显式绑定是另一种测试条件，必须单独列为旁路/指定网络实验；是否允许、是否可用依系统策略判断，不承诺一定绕开 VPN。[Network.bindSocket](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.DatagramSocket))
4. 不自动改系统 Private DNS、路由、代理客户端规则、CA、信任管理器或证书校验；只读失败不得触发权限升级。
5. 主动网络探针默认串行，既减小相互影响也便于归属。被动回调可以持续监听；未来并行实验必须声明调度方式和并发上限，并视为独立设计，不能与串行结果直接合并。

### Private DNS 与明文探针的已确认决策

官方 `LinkProperties.isPrivateDnsActive()` 文档要求 Private DNS 活动时不要发送未加密 DNS；严格模式还要求使用指定服务。[LinkProperties](https://developer.android.com/reference/android/net/LinkProperties#isPrivateDnsActive())

本产品区分普通解析与明确的协议测量：**普通/快速场景默认 raw 关闭；专业用户明确选择“协议对照”时允许发送其选定的明文 raw 查询。** Private DNS 活动或状态未知本身不锁死该专业选择，也不要求用户先换环境或关闭 Private DNS。当前已有 raw 默认关闭和执行前警示；后续是在同一计划预览中把目标、明文性质及扰动说得更清楚，不新增多层确认弹窗。

专业预览须说明：“本项主动测试指定目标的 UDP/TCP DNS，不继承系统 Private DNS 的加密解析；即使处于 VPN 下，实际外层路径仍需证据。系统 Private DNS 设置保持原样。”这是独立的诊断实验，不能作为普通应用 DNS 已受 Private DNS 保护的保证，也不能宣称该明文流量符合上述普通解析的加密要求。用户确认一次具体计划后即可执行，计划内固定目标的已批准重试不重复确认。

`POLICY_BLOCKED` 只用于实际系统/组织策略等限制，不因快照显示 Private DNS 活动就伪造一次阻断；未选择 raw 记 NOT_SELECTED，选择后发生的系统拒绝按实际错误阶段记录。

当前 Manifest 的 `usesCleartextTraffic=false` 与 raw 明文 DNS 并不互相矛盾：它不是覆盖底层 Socket 的通用拦截器。HTTPS 禁止明文替代仍须单独保持。[application 属性说明](https://developer.android.com/guide/topics/manifest/application-element#usesCleartextTraffic)

## 5. 观测、解释和结论分别存储

建议新增以下逻辑层，名称仅为数据契约草案，不代表已有 Kotlin API 或已变更报告 schema。

| 层 | 内容 | 示例 |
|---|---|---|
| L0 计划与能力 | 要回答的问题、适用范围、目标来源、允许动作、实际可用权限 | “只比较本应用默认网络上的系统与 raw DNS；HTTPS 未选” |
| L1 原始观察 | 谁在何时、哪个位置、经什么 API/协议记录了什么；保留错误阶段 | “UDP 返回 rcode=0、TC=false、1 个 A 地址”；“Android ERROR_SYSTEM code=1，errno 可得” |
| L2 完整性与关联 | 来源真实性/文件完整性、请求标记、时间窗、网络代数、重复记录、缺口 | “同一 runId、唯一回显、时间可关联”；“日志来自用户导出但身份未验证” |
| L3 有限推断 | 明确规则及前提，引用输入观察；给出替代解释 | “同域且网络稳定，系统与指定 DNS 的行为不同；类型/缓存仍可能不同” |
| L4 策略评价 | 对哪个预设策略 MATCH/MISMATCH，适用边界和证据缺口 | “本次 HTTPS 来源不在用户事先确认集合”；不写“已证明全机泄露” |

不要把三个维度塞进一个“成功/失败”：

- **能力状态**：AVAILABLE、UNSUPPORTED、UNAVAILABLE_API、PERMISSION_DENIED、POLICY_BLOCKED、RESOURCE_UNAVAILABLE。
- **执行状态**：NOT_SELECTED、NOT_STARTED、RUNNING、COMPLETED、ERROR、CANCELLED、SKIPPED；SKIPPED 必须有原因，如预算耗尽或前置条件不满足。
- **证据/推断状态**：VALID、UNVERIFIED、INVALID；以及 OBSERVED、MATCH、MISMATCH、CONFLICT、INSUFFICIENT、NOT_APPLICABLE。

现有 `Execution`/`Verdict` 可以在兼容层映射，禁止把新增状态悄悄写入旧 schema。`false` 表示明确观察到否定状态；`null + reason` 表示未知；空数组只有在采集正常且完整时才代表“观察到零项”。旧报告未记录 rcode 时保持“未记录”，不由 DNS_FAILURE、3ms 或成功的另一协议补猜。

界面首屏回答“做了什么、取得什么、还缺什么”；错误、缺失与取消优先于单项成功。不产生会覆盖子项异常的全局绿色通过。

## 6. 计划与目标从哪里来

默认只接受四类有来源的计划输入：

| 输入来源 | 可自动带入 | 必须保留的确认/限制 |
|---|---|---|
| 内置版本化场景 | 系统 DNS；同域 raw A + UDP/TCP 的字段建议；协议上限 | 选择场景只填入，不运行；显示版本和实际待发送内容 |
| 当前默认网络快照 | 可得的数字 DNS 地址及采样时刻 | 可能是 VPN 虚拟地址；不自动改用公共 DNS；网络变化后不得静默更新冻结目标 |
| 用户明确填写/选择 | 受控域名、数字 DNS、HTTPS 源、预期 IP、外部证据文件 | HTTPS 信任和预期 IP 不由本次结果自动建立；敏感目标需展示披露对象 |
| 已保存的基线计划 | 原目标、协议、查询和预算的副本 | 不从基线中的成功结果反推策略；权限/网络和实际配置仍须重新检查 |

公共 DNS 目录只提供信息，不因某个服务更快或刚好成功而自动切换。订阅、YAML、日志、HTTP 响应和第三方报告都是数据，不得从中执行命令、下载配置、启用新的端点或服从嵌入指令。

建议在执行前冻结 `ExperimentPlan`：

```text
planVersion, publicPlanId, experimentId, purpose, scope
targetProvenance[]: sourceKind, catalogVersion/snapshotTime/userSelection
probes[]: probeId, protocol, target, query, recordType, networkSelector
policy: expectedSourceIps, endpointTrustDecision, allowedDisclosure, plaintextPolicy
schedule: orderedProbeIds, maxConcurrentActiveProbes=1
budget: globalDeadlineMillis, perProbeTimeoutMillis, maxAttempts, responseByteCaps
identity: EXACT_QUERY | TEMPLATE_SAMPLES, templateVersion, noncePolicy
capabilityRequirements[], prerequisites[], stopConditions[], retentionPolicy
```

规范化后计算仅本地使用的摘要以发现计划被改动；共享导出使用随机 `publicPlanId` 和明确的可比性结果。域名/IP 等低熵值的普通哈希不是可靠匿名化，默认不公开可枚举的目标哈希。完整计划只在用户明确完整导出时提供。

执行前预检完成后显示具体计划。新增目标、协议、记录类型、网络选择器、TLS/Private DNS 策略、信任或预期 IP，均创建新的计划版本和实验；不能在失败后偷偷修改同一条计划。

## 7. 多源一致、差异和冲突

### 7.1 先定义“是不是同一个事实”

比较键至少含：被测 App/范围、协议、实际目标、问题名/记录类型、请求标记、时间窗、网络与策略版本、观察位置。HTTPS 端点看到的源 IP、权威 DNS 看到的递归源 IP、手机接口地址，是三个不同事实，不应送入多数投票。

同一域名也可能合法返回不同 CDN、地域或轮转结果；A 和 AAAA 不同、缓存命中与新查询不同、两次时间不同，都不自动构成冲突。只有两个证据对**同一限定命题**提出不能同时为真的陈述，才标记 CONFLICT。

### 7.2 记录依赖关系，不按来源数量加分

为每份证据记录 `sourceId`、`observerPosition`、`operatorId`（可得时）、`underlyingApi`、`sharedDependencies`、`independence=KNOWN_SHARED/ESTABLISHED/UNKNOWN`。没有独立性证据时使用 UNKNOWN。

- App 截图和 App JSON 是同一数据的两种展示，不是两个独立证据。
- 系统 DNS 与 InetAddress 的另一封装可能共享平台解析器，不构成新的路径观察。
- UDP/TCP 回答来自同一被接管目标时，两协议结果相同不能证明真正访问了指定公共服务。
- 两个回显站即使不同域名，也可能共用运营方、网络或 IP 数据库。
- 客户端规则命中日志与外部网关包属于不同观察位置，但需核对窗口、接口、NAT/隧道关系和同一请求归属。

### 7.3 冲突处理契约

1. 保留全部原始观察、失败、晚到和重复记录；任何解析修正以新版本附加，不覆盖旧记录。
2. 先检查身份/请求标记/时钟误差/完整性；发现不可关联时标记 UNVERIFIED 或 INCOMPARABLE，不伪装为已解决冲突。
3. 检查是否其实是不同协议、目标、阶段、配置版本或网络；成立时拆为不同实验。
4. 真冲突并列展示主张、支持证据和共同依赖，不自动选择“更新”“更绿”“多数”或“签名了”的一方。
5. 给出一个能区分解释的后续实验，新增授权计划后才运行；不能自动增加流量直到某方胜出。

签名、TLS 和文件 SHA-256 分别可以帮助确认传输/来源或完整性，但都不能单独保证日志内容真实、采集无遗漏或观察者独立。

“网关未看见 DNS”必须附带接口覆盖、过滤器、捕获起止、丢包计数、时钟误差和正对照；缺一项时只能写“该来源没有可用记录”。即便条件齐备，也只能限定为“在列明窗口和接口未观察到匹配流量”，不能推广为全机从未泄露。

## 8. 重试、预算、幂等和取消

### 8.1 当前行为与后续通用调度要求

当前专业链默认一次，用户显式选择后可在限定TIMEOUT/连接失败时追加一次；总预算20/60秒。深度网站链默认允许暂时连接/等待失败追加一次，网站总预算30秒、整体60秒；扩展DNS四项各一次。各链保留失败尝试。系统内部动作和线上包数仍未知。

下表主要约束专业链的限定复核，相关部分已在0.5.0实现；网站链的具体配置另见深度诊断契约。通用调度预检、跨后端能力和完整统一字段仍待实现：

| 项目 | 合同与实现范围 |
|---|---|
| 可重试条件 | 仅预先声明的 TIMEOUT/临时 IO 类、同一有效能力与网络阶段；无足够细节的 DNS_FAILURE 不自动猜测为可重试 |
| 不自动重试 | 用户取消、权限/策略拒绝、参数错误、证书验证失败、格式错误、NXDOMAIN、明确 DNS 错误状态、策略不匹配、真正冲突 |
| 退避 | 仅一次附加尝试前等待 500ms；每个所选探针最多一次附加尝试，整次运行共享总预算，0.5.0 不加随机抖动以便复现，记录实际等待。等待可取消，并计入同一绝对预算 |
| 调度上界 | 预先核对各探针最多耗时、退避及响应上限；不满足预算时提示用户选择更少项目或更短单项预算，不能临时无限延长 |
| 保持参数 | 服务器/端口/域名/类型/网络选择/TLS/预期策略不变；否则为新实验，不是重试 |
| 不隐式回退 | UDP 不自动转 TCP，DoH/DoT 不退明文，IPv6 不偷偷换 IPv4，目标不换公共 DNS，TLS 不跳过校验 |
| 全部保留 | 每次 attempt 的开始/结束、触发原因、结果与预算消耗均保存；成功不删除第一次超时 |
| 汇总 | “2 次尝试中 1 次返回地址、1 次超时”；不能显示“已修复/稳定通过”，也不能只导出成功样本 |

这些是本项目的调度约束，部分通用预检仍待实现，不宣称协议规范要求对所有失败重试。HTTP 的幂等性和可自动重试条件也不允许无穷重放；客户端不应自动再次重试已经失败的自动重试。[RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)

### 8.2 “幂等”不等于“不会改变观测环境”

DNS 查询可能填充缓存、触发日志和限流；HTTPS GET 也会产生日志、连接和计数。因此即使功能语义可重放，后一次尝试也不天然独立或与第一次同条件。报告必须显示顺序、间隔和可得缓存信息。

每次尝试使用唯一 `attemptId`；HTTP 回显标记归属于该尝试，不接受其他尝试的响应。DNS 事务 ID 只帮助匹配报文，不是服务身份认证或跨网络日志的全局标识。DNS 字面问题名的变化另按第 9 节处理。

现有 ProbeAttempt 已记录尝试与预算；下面是后续统一模型的扩展合同，不是当前导出字段全集：

```text
Attempt: experimentId, publicPlanId, runId, probeId, attemptId, attemptIndex
         networkEpoch, startMonotonic, deadlineMonotonic, endMonotonic
         execution, failureStage, failureCode, responseSummary
         retryTrigger, backoffMillis, logicalAttemptCount, wireAttemptCount
         evidenceIds[], lateCallbackCount, stopReason, cleanupStatus
```

重试状态机为 `ATTEMPT_RUNNING → COMPLETED / ERROR`；仅 ERROR 满足预先允许的临时性条件、次数与预算时进入 `RETRY_WAIT`。退避结束后再次检查取消、能力和网络阶段，再创建新 attempt；任一条件失败即结束，不发包。取消可从运行或等待进入 STOP_ACCEPTING；没有 `直到成功` 的循环。

### 8.3 停止与资源释放

拟议状态流：`PREPARED → RUNNING → STOP_ACCEPTING → CLEANING → TERMINAL`。用户取消、预算耗尽、关键前置能力消失后，立即禁止新探针和重试；取消队列中的退避；冻结结束时可用证据；关闭 socket/取消系统查询/断开 HTTP。清理过程不在主线程阻塞，不因清理迟缓偷偷开启下一任务。

晚到回调只可作为带标记的诊断记录，不能把已经取消的结论改成成功。全局截止使用单调时钟；UTC 只用于跨源关联，必须携带时钟误差。预算达到表示“不再接收新证据”，不能承诺 OS 资源已经在同一毫秒释放。若释放未确认，显示状态并禁止并发新实验，不谎报空闲。

## 9. “同计划复测”与随机 DNS 标记不能混为一谈

需要两个明确模式，不能同时声称既完全相同查询、又每次使用新域名避开缓存。

### A. EXACT_QUERY：同一字面查询的可重复观察

计划固定域名、类型和目标。系统与 raw 默认同域，raw 为 A；系统类型仍由平台选择。重试继续使用相同字面域名，承认后续可能命中已被前次加热的缓存。当前 `ReportComparison` 的严格计划比较适用于这种模式，不把同配置等同于相同隐藏网络状态。

### B. TEMPLATE_SAMPLES：同一实验设计下的不同样本

仅用于用户控制的测试域、已知权威记录及日志。预先固定模板、生成规则、期望 RR/TTL 和样本数量；每个样本产生不同标记，例如 `<random>.<channel>.<controlled-zone>`。`experimentSpecId` 相同，`materializedPlanId`、`sampleId` 和实际 QNAME 不同。页面必须写“同一设计的不同样本”，不能写“完全相同目标复测”。

新随机名称可以减少某些精确名称缓存的复用，但不能保证无缓存、没有负缓存/通配策略、DNSSEC 激进缓存或上游复用。不得把它描述为强制冷启动或绕过所有缓存。

需要按通道归属权威日志时，系统、UDP、TCP 可以使用不同 channel 名称；这样**问题名已经不同**，只适合该模板契约下的归属实验，不能同时当作同一字面问题的严格解析对照。若三个探针复用完全相同 QNAME，则缓存可能阻止后两项到达权威；权威看到的 UDP/TCP 也是递归服务器到权威的协议，不等于手机发起的协议。

对一次失败换新随机 QNAME，应新建一个样本并记入样本预算，不能记为原问题的成功重试。不得在当前 `ReportComparison` 内偷偷忽略实际域名差异；模板比较需要另加明确契约和版本，尚未实现。

## 10. 缺权限、网络变化和外部证据接入

预检按能力逐项记录。缺少网络状态、API 不支持、用户拒绝导入、服务不可达、系统禁止目标，不能合并为“DNS 服务器失败”。权限与配置来源未知时，不自动申请 root、不启动 ADB、不扫描本机或局域网、不安装证书、不扩大目标集合。

当前专业和深度链都会在观察到网络变化时停止后续实验，保留前后快照与停止原因。标准化 networkEpoch 和有意切网的多阶段实验尚未实现。显式切网实验需另行声明阶段，不能混入稳定网络复测。

客户端只读集成先支持用户导出的限量文件，再评估已知客户端的正式接口。接口地址、认证及支持版本必须明确；凭据只进内存，不写错误、日志或导出。读操作白名单和响应大小上限在计划内，禁止调用切换代理、更新订阅或重载配置接口。收到不支持版本即退出，不猜字段含义。

外部证据导入合同至少包括：

```text
sourceId, sourceKind, observerPosition, ownerDeclared, authenticationStatus
artifactHash, parserVersion, capturedAtUtc, clockUncertaintyMillis
coverage: interfaces, addressFamilies, protocols, filter, window, droppedRecords
correlation: runId/attemptId/sampleId or exact query + bounded time window
observations[], rejectedRecords[], redactionApplied, sharedDependencies
```

导入是解析数据，不是执行脚本。限制文件字节数、记录数、嵌套和处理时长；保留拒绝原因但不回显秘密。没有时间误差、窗口或可靠请求关联的日志可展示，不能直接升级为路径证明。网络采集器自身产生的认证、引导和日志下载流量也需标注，避免把“收集证据”的流量误认成被测探针。

## 11. 可落地示例

### 示例 1：用户提交的 0.3.0 脱敏报告

`proxy-evidence-c9ece9df-redacted.json` 记录：系统 DNS 为 ERROR/DNS_FAILURE；raw UDP/TCP 为 COMPLETED、rcode=0、TC=false、有地址；HTTPS 为 NOT_STARTED；快照出现 VPN 能力。旧文件没有系统 DNS 细分错误字段，且两种查询域名都变成 `[REDACTED]`。

允许的摘要：“系统 DNS 报错；UDP/TCP 返回地址；HTTPS 未测。实际路径与根因未确定。”

不允许的推断：“因为 3ms 失败所以权限问题”“DNS 被污染”“Clash 泄露”“两条 `[REDACTED]` 相同所以是同域严格对照”。下一步先使用本地未脱敏配置确认是否同域，再用支持详细错误阶段的版本复测；不为了得到成功而自动换服务器。

### 示例 2：Private DNS 已活动

预检得到 `privateDnsActive=true`。普通快速检查保持 raw 未选，仅执行该计划已有项目。用户进入专业协议对照并明确选择 raw 后，同一计划预览显示数字目标、查询、明文性质和“不继承系统 Private DNS”的边界；开始后允许该诊断查询，Private DNS 不被修改，也不要求先切换环境。若系统实际拒绝，记录真实拒绝，不预先把它写成 UDP/TCP 不可达或 POLICY_BLOCKED。状态未知时展示未知，仍保留专业选择。

### 示例 3：一次超时，附加尝试成功

预先允许 2 次的同域 UDP 可达性复核，第一次超时，退避后第二次收到地址。保留两份记录，显示“1/2 次返回地址，存在不稳定观察”。只说明后一次取得了回答；不判定稳定、真实解析器身份或隐私修复。若第二次改为 TCP，则是新探针/新实验，不能记成 UDP 重试成功。

### 示例 4：客户端日志与网关证据表面冲突

客户端写“规则选择代理”，网关出现去 DNS 目标的 UDP 包。先检查该包是否真属于本次标记、是否是另一次 bootstrap、观察的是隧道内还是外、时间与接口是否覆盖。关联不足时输出“待关联”；只有能对同一禁止直连命题建立关联时才标有限 MISMATCH/CONFLICT，仍保留客户端记录。不能仅按目的 IP 或更可信的品牌选择一边。

### 示例 5：加密 DNS 与 HTTPS 来源不同

DoH 端点和 HTTPS 回显端点不同，来源/路径也可能不同。分别形成观察；二者没有共同预期策略时不能叫作冲突。DoH 成功只支持该 DoH 交换，不支持“所有系统 DNS 已被加密”或“所有请求经代理”。

## 12. 隐私、保留和导出

默认只收集回答选定问题所需的信息。请求前展示目标方将得到的域名/标记、来源网络信息及协议。随机标记不可包含设备 ID、账户、订阅、节点名、安装标识或稳定用户标识；实验结束后不继续后台采样。

当前进程内结果/基线与用户主动导出的文件分开管理。拟新增证据历史默认关闭；如后续用户明确启用，再确定数量/时长上限、存储位置、逐次删除和全部清除方式，不随 P0 审批自动启用。完整外部日志不默认复制进长期历史，只保存经过选择的片段及来源信息。

拟议默认导出移除原始域名、IP、网络标识、敏感路径、DNS 随机名称和凭据，保留必要状态、阶段、响应码、预算和覆盖缺口；为报告内关联保留新生成的 runId/attemptId 等非稳定标记，并说明它们仍可用于关联。本次不改变现有 schema 2 的脱敏字段，当前专业RunReport导出中的 runId 和固定 `/v1/echo` 路径仍会存在。允许用户单独选择完整导出，界面说明文件仍包含网络标识；只删除本地记录不能撤回收件人、云文档提供者或服务端已有日志。

脱敏可能损失可比性：两个 `[REDACTED]` 不代表原值相同。建议导出明确的本地派生字段 `sameQueryHost=true/false/unknown`、`samePlan=true/false/unknown` 及计算规则版本；它们是导出者的声明，不是第三方能从隐藏数据独立重算的证明。普通 SHA-256 也不将低熵域名/IP变成匿名数据。

外部服务的日志保留由其控制；不能承诺“清除 App 结果即可清除 DNS 服务日志”。不要为收集更多证据自动上传配置或完整流量，也不把凭据放入错误文本。

## 13. 确认后的分阶段实现与验收

以下为验收合同清单，不能把它整体标为未实现或已通过。单槽、有限错误码、尝试记录、固定预算及切网停止已实现；外部日志导入、模板样本、能力协商和新协议仍待实施。具体已跑记录从当前验证索引进入，未来项目仍需逐项取得证据。

### 现有探针的证据质量合同（P0 文案回归、P1 数据与执行闭环）

| 编号 | 验收合同 |
|---|---|
| A01 | 选择场景、读目录、看摘要不会发送探测；开始前展示冻结目标、协议、预算与披露对象 |
| A02 | 缺失、未选、未执行、取消、错误分开；未知 Private DNS 不显示 false；旧报告未记录的字段不补猜 |
| A03 | 系统 DNS 报错且 raw 成功时逐项展示；域名隐藏/不同或网络不稳时不定位系统解析故障 |
| A04 | 记录系统回调阶段及数值错误；rcode、resolver code、errno 不互相映射，不导出异常原文 |
| A05 | 专业默认单次；深度网站按其计划限定复核；UDP读取轮询不增加发送次数、不重置绝对截止 |
| A06 | 请求取消、预算耗尽与晚到回调竞态下不发新请求、不覆盖终态；清理未确认时不启动并发任务 |
| A07 | 同一网络 ID 的 DNS/能力变化也使条件不再稳定；切网停止与可比性降级分别验证，不能静默跨网续跑 |
| A08 | 普通基线比较检查实际目标/问题/类型/策略/预算；改目标后明确新实验；不把随机 QNAME 当原字面查询 |
| A09 | 保持正常 HTTPS 信任、请求标记和响应验证；不把 DNS 成功、取消或 TLS 错误改写为出口 MATCH/MISMATCH |
| A10 | 测试目标/错误文案/原始日志中的凭据不进入摘要和默认导出；脱敏后不得重新推断被隐藏值相同 |
| A11 | 普通/快速默认 raw 关闭；Private DNS 活动或未知时，专业协议对照仍可明确选择 raw；统一预览说明明文和扰动，不改 Private DNS、不多层弹窗、不伪造 POLICY_BLOCKED |

### 有限重试与冲突合同（P1；外部日志接入归 P3）

| 编号 | 验收合同 |
|---|---|
| B01 | 专业链默认 1 次；明确启用时最多 2 次且总预算不延长；退避可取消；无剩余预算时不发送 |
| B02 | 第一次失败、第二次成功都出现在页面和导出中；不能仅挑成功样本或自动提高隐私结论 |
| B03 | 导入重复、冲突、时间超窗、时钟不明、无来源/被篡改、超大及恶意结构文件，分别给出有界拒绝或未知状态 |
| B04 | 同源截图+JSON、相同运营方的多接口不增加独立证据数；真冲突不能被多数投票消除 |
| B05 | 捕获接口遗漏、正对照失败或丢包信息缺失时，不输出“未发现所以安全”；只能陈述观察覆盖范围 |
| B06 | TEMPLATE_SAMPLES 的全部样本数预先固定并完整显示；更换 nonce 不伪装成同一字面目标重试 |

### 新增协议与外部能力合同（P3；特权与跨应用专项另行审批）

| 编号 | 验收合同 |
|---|---|
| C01 | DoH/DoT 独立验证 TLS、引导、失败阶段和禁明文回退；成功不升级成强制代理或全机隐私保证 |
| C02 | IPv6 区分 RR、socket 目标、内层及外层；双栈回退必须可见，不能借 IPv4 成功补成 IPv6 成功 |
| C03 | UDP/QUIC 使用各自受控服务与协议结果；TCP/UDP 53 成功不能使其默认通过 |
| C04 | 客户端集成严格只读白名单、版本适配和认证；不扫描控制口、不调用状态变更、不把内置上游代理等同原客户端 |
| C05 | 同用户 VPN 占用不会被本工具自动替换；需要 root/ADB/网关时显示外部依赖，拒绝不会偷偷走别的权限路径 |
| C06 | 实体设备/真实 VPN 验收按具体设备、OS、客户端版本、配置、协议与网络条件单独记录；模拟器回环不能代替 |

## 14. 推荐默认与阶段授权

阶段状态由产品总纲与当前实现记录维护。本分项不重复要求确认已实施项目；未来扩大目标或使用特权后端按实际任务授权处理。

1. P0 先做演示语义、UI/Material 3 和导航；P1 证据质量与分类重试；P2 修复闭环；P3 新协议/外部证据；P4 特权及高级专项单独评审。
2. 专业链默认一次尝试；明确选择瞬时故障复核时最多一次附加尝试，固定目标且保留全部结果；深度网站链依照独立计划。
3. 普通/快速 raw 默认关闭；专业明确选择允许明文协议对照，统一预览披露边界，不自动修改 Private DNS，不锁死专家选择。
4. 外部证据作为后续阶段能力，优先用户导入的受控日志；客户端 API 默认关闭且只读白名单，后台采样和特权能力继续关闭。
5. 默认不保存敏感配置；如后续需要历史保存，再确定保留上限、存储位置和清除方式，完整导出始终单独选择。

本规格的最低交付应是：每条结论都能回到明确的计划和观察；缺口、失败、冲突与样本选择均可审计；没有必要证据时清楚写出不知道，而不是以增加请求次数制造确定感。
