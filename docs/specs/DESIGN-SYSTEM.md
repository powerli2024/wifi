## 1. 产品定位与优先级

产品是面向代理使用者和技术学习者的**诊断、配置审查与复测工具**。主要任务是把“哪里异常、现有证据能说明什么、下一步怎么核查”说清楚，并减少专业实验的重复输入。它不替换现有 VPN，也不承诺凭一次 DNS 响应证明整台手机没有泄露。

默认优先级为：证据准确 → 专业任务可完成 → 输入少且可控 → 反馈清晰 → 视觉一致。专业性体现为正确的目标、协议、状态与建议；不靠把所有字段、原始枚举和免责声明堆在首页实现。

- 常用任务先给可核对的默认值；高级参数按需展开，不能静默填入虚构的实际端点、预期出口或信任状态。
- 页面解释“当前是什么、下一步做什么”；完整原理和局限放在详情与帮助中。
- 每次启动测试计划确认一次精确目标与预算；已批准预算内的同目标重试无需再弹窗。增加目标、扩大协议范围或超过预算时，作为新计划重新确认。浏览页面、展开详情、填入空表单建议、查看示例无需额外确认。
- 不增加 root、VPN 接管、辅助服务、账号、遥测或后台自动探测作为完成基本任务的前提。

## 2. 采用的规范与不采用的外观

采用 **Material 3 的成熟组件模式与语义角色**，结合 Android 官方 Settings 的分组、当前值、依赖状态和上下文说明方式。这里采用的是交互规范，不是复制 Google 品牌、Google Sans 字体、彩色标志或某个 Google 应用的页面。暂不引入复杂 Expressive 动效、品牌展示页或为视觉效果制造多层卡片。

| 规范依据 | 本产品采用的部分 | 本产品自己的取舍 |
|---|---|---|
| [Material 3 色彩角色](https://m3.material.io/m3/pages/color-roles?s=m3) | 用语义角色区分表面、正文、主操作、边界和错误；前景与背景配对 | 采用下文自有青绿色建议色板，数值不是 Google 官方值 |
| [Material 3 字体角色](https://m3.material.io/styles/typography/applying-type) | 标题、正文、标签各司其职，避免全部文字同一权重 | 中文正文优先系统字体；详细 IP/代码可用等宽字体，无在线字体依赖 |
| [官方 Material Android 导航栏](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomNavigation.md) | 紧凑设备用少量主要目的地，明确选中状态和标签 | 默认三个目的地；一次运行报告是详情，不占一个常驻标签 |
| [官方 Material Android 文本字段](https://github.com/material-components/material-components-android/blob/master/docs/components/TextField.md) | 持续标签、支持文字、聚焦和错误状态 | 使用有边界的字段；格式示例与错误就近显示，不依赖 placeholder 承载字段名 |
| [官方 Material Android 对话框](https://github.com/material-components/material-components-android/blob/master/docs/components/Dialog.md) | 需要决策时集中呈现关键内容与明确动作 | 每次启动测试计划确认一次；保存配置使用预览和系统文件窗口，不层层弹免责框 |
| [Android Settings](https://developer.android.com/design/ui/mobile/guides/patterns/settings) | 小组、当前状态、依赖项、上下文入口、尊重系统设置 | “修复”是本产品核心工作流，不是杂项设置页，因此进入主要导航 |

核查方式：官方 Material 3 网站的色彩与字体资料及官方 Material Components Android 的 M3 对应组件文档；部分 M3 页面正文依赖 JavaScript，因此组件细节使用其官方实现仓库文档交叉核对。以上引用不是本应用已通过 Material 一致性认证的声明。

## 4. 信息架构：概览 / 测试 / 修复

| 目的地 | 解决的主要问题 | 一级内容 | 次级内容 |
|---|---|---|---|
| 概览 | 现在是什么情况，下一步做什么 | 当前运行状态、一次快速检查、最近观察摘要、查看报告 | 近期记录入口、帮助、版本信息；无数据时显示真实空状态 |
| 测试 | 我要验证什么，参数怎样填 | 系统解析、DNS 对照、HTTPS 出口三个任务模板；所选任务字段 | 独立组合与高级选项、填写指南、协议契约 |
| 修复 | 哪些证据值得行动，如何保留原件并复测 | 证据对应建议、配置审查/预览/保存、系统设置入口 | 修改限制、回退说明、关联本次基线 |

报告属于某次运行：从“概览→最近检查”、当前检查完成或基线对照进入“检查详情”。详情显示运行时间和来源，返回回到原目的地；不创建第四个“报告”或第五个“历史”空页面。尚无记录时不显示假的历史列表，也不把离线演示混进实际记录。

在紧凑手机上保持三个主要目的地可发现；主操作不放进导航栏。检查详情、配置预览和导出属于任务内层，可隐藏底部主导航并提供返回。用户切换到别页或应用在后台时，完成事件只更新状态，不强制抢回报告页。当前任务发起后仍停留在测试流程内时，可自然进入该次运行详情。

以下文字线框表示目标信息层级，不是已经实现的截图。方括号表示可操作项；状态来自真实报告或明确空状态。

## 6. 导航、概览与报告详情

概览首屏顺序为：标题与一句用途 → 当前运行/最近观察 → 快速检查主操作 → 测试与修复入口。只在无报告时显示“尚未检查”，有报告时展示其时间和限定结论；不要同时展示空状态和成功状态。快速检查默认系统 DNS，原始 DNS 明文对照为明确选项，不能因为低输入目标而默默启用。

专业诊断 RunReport 的报告详情按以下顺序呈现；深度报告采用独立分层布局及深度基线，不与专业基线互换：

1. 来源与标题：真实运行、离线演示、未完成分别明确标记；标题来自观察，不猜根因。
2. 四行状态：系统 DNS、UDP、TCP、HTTPS；每行状态与一句解释，未启用写未执行。
3. 主要下一步：一项最有意义的动作，例如检查查询域名、查看某项错误、保存基线或进入修复建议。
4. 详细证据：目标、耗时、响应码、网络快照、完整诊断与局限，按组展开。
5. 对照与导出：保存基线、相同计划复测、脱敏导出；动作只在具备前提时启用并说明缺什么。

0.7.0 深度报告的实现顺序与行为：

- 固定工具栏：返回与“导出”；后者只在报告可用、未运行且没有导出票据等待处理时启用。
- 顶部状态卡：执行时显示当前项目，完成时显示停止原因或网站/本机主要结果。解释 HTTP 代理解析的辅助内容放在证据区，不能盖过本次连接/TLS 故障。
- 表单保留网址、代理声明、原始 DNS 选项与明文提示；开始、本机实验、取消在该任务区域。报告动作放在长证据之前，包括单报告导出、保存基线、原计划复测和双报告导出。
- 五行阶段表显示状态和耗时，补充 HTTP 状态、协议、TLS 版本和总耗时；存在复核时明确保留首次观察，完整尝试可展开查看。
- 定位依据、网站证据与说明、网络画像、本机检查、原始 DNS、比较条件默认收起。按钮文字明确“展开/收起”，展开不联网；旋转保留当前报告的展开状态，新报告默认收起。
- 保存/替换基线需确认当前报告；失败实验可以保存，取消、换网和缺测等不完整报告禁用保存并解释原因。复测确认说明原计划、原始明文 DNS 目标和预算，输入框的新编辑不静默覆盖冻结计划。
- 比较前提不满足时显示条件冲突，允许导出两份原报告；不显示虚构改善、因果修复或安全通过。基线仅在进程中保留，需要留档时导出。

单报告与双报告保存窗口沿用冻结载荷与唯一导出身份。旋转和清除当前报告不改变待写载荷，旧保存回调不能接走新的票据；进程丢失原载荷后提示重新导出。打开系统设置或代理只读协同页面只导航，采集另行确认；专业测试、网站资源释放、深度诊断及代理只读协同忙碌时不重叠启动。

例如当前用户初测适合概括“系统解析未取得地址；UDP/TCP 记录了地址响应；HTTPS 未执行”。脱敏后的同一占位符不证明原域名或地址相同，`Private DNS=false` 不等于明文泄露。演示中的每一条诊断也必须使用“示例显示/虚构结果”等来源语义；不能仅靠页面最上方一次标签让后续句子看起来像设备事实。

## 7. 专业表单：少输入，保留控制权

先选任务，再填必要字段。默认系统 DNS 域名为 `example.com`；DNS 对照可以显式沿用该域名、端口 53、A、UDP/TCP，并提供当前网络 DNS 的填入动作。网络没有可用 DNS 时说明原因，不随意填公共服务器。HTTPS 没有通用自动端点：必须由用户填写兼容服务；预期 IP 允许空白，信任只能人工确认。

| 交互 | 目标规则 |
|---|---|
| 使用空表单任务模板 | 直接填写并显示一行“已填入，尚未执行”；无需先弹确认 |
| 模板将覆盖非空自定义字段 | 仅此时显示要替换的字段并确认一次；不得抹掉无关草稿 |
| 关闭项目 | 隐藏/禁用依赖字段并保留草稿，隐藏项不参与校验和探测 |
| 点击开始 | 校验启用字段；首个错误就地说明并定位，不再叠加重复的全局“配置错误”弹窗 |
| 地址/域名输入 | 持续标签、格式例子、正确键盘；端口数字键盘，IPv6 字段允许冒号，不强制数字键盘 |
| 键盘“下一项/完成” | 移动焦点或关闭键盘，不能跳过目标确认直接请求网络 |
| 长说明 | 标签下保留一行用途/当前状态；协议、缓存、日志取证细节用“填写指南”展开 |

HTTPS 需要正常 TLS、HTTP 200、`application/json`、正确的本次请求标记和来源 IP 格式；普通查 IP 页面、订阅或 DoH URL 不算兼容端点。完整契约由帮助页承载，不在每个输入框下重复。原始 A/AAAA 是记录类型，不是外层传输路径；“IPv6 在范围内”也不是开启手机 IPv6 的开关。

## 8. 修复中心与确认边界

修复首页以当前证据和可选行动分组：配置文件审查、系统网络设置、修改后复测。没有报告仍可手动审查配置，但说明“未关联诊断”；不能编造一个已发现的漏洞来推动用户使用修复。

| 步骤 | 主要显示 | 确认与反馈 |
|---|---|---|
| 选择配置 | 支持的格式与大小、文件选择入口 | 使用系统文件窗口；取消返回原状态，不重复索取广泛存储权限 |
| 审查 | 可处理/不支持/需人工处理，隐藏敏感原文 | 不支持时不生成“修复成功”按钮，不请求其中的订阅 URL |
| 修改预览 | 逐项列出原值摘要→新值、保留字段、影响和未覆盖范围 | 预览页承担决策信息，不再叠加内容相同的确认弹窗 |
| 保存副本 | 明确原件保留、完整副本可能含凭据 | 一次明确保存动作进入系统创建文档窗口；系统窗口不是证明副本已应用 |
| 手动应用 | 提示由代理客户端校验并导入，注意最终配置覆盖 | 应用不声称系统/代理配置已变更；返回后不自动重测 |
| 复测 | 选择已保存的基线，核对冻结的计划 | 启动复测计划确认一次；已批准预算内同目标重试不再弹窗；比较只描述现象，不宣告因果修复 |

打开网络/VPN 系统设置不需要应用再问一次“是否打开”；入口不可用时提供可读说明和通用设置入口。系统 Private DNS 主机名、代理内核 DoH URL 和原始 DNS 数字 IP 必须分开命名，不能用一个“DNS 地址”字段混装。

对话框只用于需要立即决定的事项：启动测试计划、覆盖自定义输入、确认完整敏感导出等。每个对话框说明本次动作与影响，提供动词明确的主操作和取消；同一信息已在方案预览中展示时不再套一层确认。字段错误就地显示，短暂完成状态用页内提示，耗时过程留在原页面，不用连续弹窗串联流程。

## 9. 状态、错误、冲突与权限

| 状态 | 用户应看到什么 | 操作规则 |
|---|---|---|
| 空白 | 当前没有报告/基线，怎样取得第一份结果 | 提供一个相关主操作，隐藏无意义的结果占位列表 |
| 运行中 | 正在进行的项目、已完成项目和取消入口 | 不虚构百分比；可以浏览其他目的地，不能重叠启动 |
| 已取消、正在释放 | 停止接受新证据，仍等待资源释放 | 不把按钮重新点亮当作释放完成；等待真实控制器状态 |
| 输入错误 | 对应字段、具体格式与纠正方法 | 保留其他值，优先就地错误，避免错误弹窗循环 |
| 网络/协议错误 | 固定错误类别、已取得的有限证据、建议下一步 | 不显示异常原文/凭据，不把超时称作成功阻断 |
| 条件冲突 | 不同域名、网络变化、目标变化、过期基线等具体原因 | 允许看原始观察，但不能生成虚假的改善/退化结论 |
| 导出/文件操作中 | 当前动作与忙碌状态；失败时说明是否可能留下不完整副本 | 防重复操作，保持已冻结载荷和身份校验，不静默改写原件 |
| 不支持的配置 | 不支持的结构与可行的手动处理方式 | 原件保留，不降级为“尽量改”或伪成功 |

当前基础权限是 `INTERNET` 与 `ACCESS_NETWORK_STATE`；文件通过 SAF 由用户选择。基线不要求新增 root、VPN 或无障碍服务权限。实际系统拒绝、无提供者或设置入口不可用时才解释具体限制，不在首次启动制造一页与任务无关的权限申请。

帮助和边界采用三层：首屏一句范围 → 与当前操作相关的一句提示 → 完整证据与帮助。关键的明文目标、完整副本含敏感信息和未验证路径应出现在对应决策点；其余限制不必在每一张卡片重复。

## 10. 可访问性、暗色、字号与布局验收

目标默认跟随系统主题，不覆盖用户的字体大小或辅助技术偏好。暗色需要独立配色和控件状态，不能依靠把浅色画面强制反色；官方 Android 建议避免硬编码浅色值，并用主题属性或夜间资源承载配色。[Android 暗色实现](https://developer.android.com/develop/ui/views/theming/darktheme)

验收下限是普通正文对比度 4.5:1、大文字 3:1、触控区至少 48×48 dp；文本状态不只靠颜色。字段 label 与控件关联、导航选中态、组标题、展开/收起和错误应能被 TalkBack 识别。[Android 无障碍建议](https://developer.android.com/guide/topics/ui/accessibility/apps)

| 验收维度 | 必测条件 | 通过条件 |
|---|---|---|
| 信息架构 | 三个主目的地、运行详情、修复预览、返回 | 当前区域明确，返回不丢进程内草稿；无空标签、无后台完成抢页 |
| 专业流程 | 系统 DNS、raw-only、HTTPS-only、自定义组合 | 只要求启用项输入；模板/浏览不联网；确认目标完整准确 |
| 来源与边界 | 真实报告、演示、缺失、取消、网络变化、脱敏报告 | 不混淆来源；不从错误/占位符/响应推导泄露或安全 |
| 亮/暗主题 | 系统浅色和深色，包括对话框、键盘与系统栏 | 无浅底白字、深底黑字、刺眼固定白区；状态颜色与文字均可辨 |
| 字号 | 系统默认、放大与 200% 字体设置 | 重要文字/按钮不截断，可换行或增高；没有靠缩字隐藏问题 |
| 屏幕与输入 | 360 dp、412 dp、较宽窗口，横竖屏、键盘开关、分屏 | 内容可达，主操作不在手势栏或键盘下；宽屏不无限拉长表单 |
| 辅助技术 | TalkBack、焦点顺序、外接键盘 | 字段用途、错误和导航状态可理解；隐藏项不成为焦点；焦点不会被持续刷新抢走 |
| 生命周期 | 旋转、切换页面、保存窗口、后台返回、进程丢失 | 沿用冻结/单槽契约；无重复运行；丢失载荷明确失败，不伪造结果 |

这里列出的是目标验收矩阵，不是本轮已跑记录。用户已要求本轮跳过模拟器检查；未覆盖项继续按[专业指南](../guides/PROFESSIONAL-TESTING.md)和[0.6网站步骤](../releases/0.6.0/TEST-GUIDE.md)验收；已取得首轮有限真机证据，范围见[当前验证](../testing/CURRENT-STATUS.md)。按实际实现范围分别记录自动化和设备验收，不用本文件替代测试证据。

## 11. 已确认的取舍及后续边界

“概览 / 测试 / 修复”、报告子页、Material Components Views、进程内草稿与默认脱敏已确认并实施；不再作为待用户批准事项。保留现有controller与探针，不因视觉整理重写网络层。后续持久历史、Compose重写及新的敏感权限均不是本基线已实现项。

维护时以本规范描述交互要求，以当前实现架构说明实际行为，以独立测试记录说明验证范围。
